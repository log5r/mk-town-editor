# 入力中のプレビュー点滅

## 原因

`DocumentAnalysisStore` は非同期解析中も直前のスナップショットを保持していた。一方、`EditorWorkspace.previewPane` は本文とスナップショットが一致しない間、プレビューへ `nil` を渡していた。このため、文字入力のたびにプレビュー全体が `ProgressView` と入れ替わり、スクロールビューも破棄されていた。

## 表示と操作の扱い

`PreviewPresentation` は完了済みのスナップショットとその本文を組にして返す。入力中はこの組を表示し、最新世代の解析が完了すると表示を更新する。空の文書も解析済みなら表示を保持できる。初回解析前とMarkdown方言の不一致時は読み込み表示を使う。

表示中の本文が編集本文と異なる間は、チェックボックス操作、原文移動、見出し移動、プレビューからエディターへのスクロール連動を実行しない。ただし、構造化プレビューの選択に使うコールバックは保持し、解析待ちのたびに別のビューへ切り替わることを防ぐ。通常の入力ではナビゲーション要求も保持し、解析完了のたびに同じスクロール移動を再実行しない。

同じ原因を調べたところ、一時停止中の手動更新でも `PreviewUpdateController.capture` がスナップショットを消去していた。ここでも直前の解析結果を残す。別ウインドウのプレビューにも表示本文と解析結果の同じ組を渡す。別ウインドウの通常更新とスライド表示は同期解析を使っており、今回の読み込み表示への切替はない。埋め込み文書の更新は既存の表示を保持している。

## 検証

`DocumentAnalysisStoreTests` で連続入力、全文削除、解析前後の表示本文、古い表示からの操作抑止、初回表示、方言変更を確認する。既存テストで古い世代の解析結果の破棄とUndo相当の本文復帰も確認する。`PreviewAccessibilityTests` では一時停止中の更新が直前のスナップショットを保持し、完了後に最新の結果へ置き換わることを確認する。

実画面での入力とスクロールの目視確認は未実施。
