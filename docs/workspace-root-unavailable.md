# ワークスペースのルートが読めないときにサイドバーが空になる問題

ワークスペースとして開いたフォルダが削除・移動された場合、外部ディスクが取り外された場合、サンドボックスのアクセス権が失効した場合に、サイドバーはフォルダ名の下に空の一覧を表示するだけだった。中身のないフォルダと区別できず、原因も対処も示されなかった（Issue #36）。起動時に古くなったブックマークも、通知なしに破棄されていた。

## 原因

- `WorkspaceFileIndex.scan` はルートの `contentsOfDirectory` の失敗をサブフォルダと同じ `try?` で握りつぶし、空配列を返していた。`WorkspaceStore.refresh()` はその空配列を `nodes` として公開していた。
- `WorkspaceStore.init` は、ブックマークが古い（`bookmarkDataIsStale`）か解決できない場合に何もせず、ルートを未選択のままにしていた。
- `errorMessage` を設定するのは `chooseFolder` のブックマーク保存失敗だけだった。

同じ `scan` を使うフォルダ全体の検索（`WorkspaceSearch.report`）、添付ファイルの確認（`WorkspaceAttachmentAudit.scan`）、移動計画（`WorkspaceFileOperations.planMove` と `WorkspaceMovePlan.validateCurrentState`）も、ルートを読めないときに「該当なし」として振る舞っていた。

## 設計判断

### ルートの失敗とサブフォルダの失敗を分ける

`scan` はルートを列挙できないときに `WorkspaceRootUnavailableError` を投げる（typed throws）。理由は `missing`（存在しない）、`permissionDenied`（権限がない）、`notDirectory`（フォルダではない）、`other` に分類する。分類には `contentsOfDirectory` が返す `NSCocoaErrorDomain` のコードを使う。2026-10-08に確認した値は次のとおり。

| 状況 | コード | 下位エラー |
| --- | --- | --- |
| 存在しない | 260 (`fileReadNoSuchFile`) | POSIX 2 |
| ファイルを指定 | 256 (`fileReadUnknown`) | POSIX 20 (`ENOTDIR`) |
| 権限なし（`chmod 000`） | 257 (`fileReadNoPermission`) | POSIX 13 |

読めないサブフォルダは従来どおり空のフォルダとして一覧に残し、`skippedDirectories` に数える。サイドバーは件数を「読み込めなかったフォルダ: N件」と表示する。サブフォルダ1つの失敗でワークスペース全体を使えなくすると、権限の違うフォルダを含む作業フォルダを開けなくなるためである。

### 利用不可の状態ではルートを保持する

`WorkspaceStore` は `rootUnavailableError` を公開する。このときも `rootURL` は残す。どのフォルダが読めないのかを表示でき、フォルダが戻ったときに同じルートを読み直せるからである。一方で `nodes` は空にする。以前の一覧は存在しないファイルを指している可能性がある。

`refresh()` が読み込みに成功すると状態は `nil` に戻る。読み直しの契機は次のとおり。

- ルートのファイル監視（FSEvents の `WatchRoot`）がルートの削除・再作成を通知したとき
- アプリが前面に戻ったとき（`NSApplication.didBecomeActiveNotification`）
- ボリュームがマウントされたとき（`NSWorkspace.didMountNotification`）
- サイドバーの「再試行」、またはメニューの「ファイル一覧を更新」

後の2つは利用不可のときだけ読み直す（`refreshIfRootUnavailable()`）。正常なときの更新頻度は変えない。

### サイドバーの表示

一覧の代わりに `ContentUnavailableView` で「フォルダにアクセスできません」、理由、フォルダのパスを表示する。操作は「フォルダを選び直す…」と「再試行」の2つにした。選び直しはパネルで追加の入力が必要なので、Human Interface Guidelines に従って省略記号を付ける。パネルは前回のフォルダの親から開く。ファイル名で開く、日付ノート、タスク、作成、並び順とフィルター、バックリンク、リンクのグラフ、Wikiリンク、分割・結合、メニューのフォルダ全体の検索・置換は、利用不可の間は使えないようにした。空の一覧に基づいて「該当なし」と表示することを避けるためである。

### 古いブックマーク

ブックマークの扱いは `WorkspaceStore.restoreBookmark` にまとめた。

- 解決でき、古くない: そのまま開く。
- 解決でき、古い（フォルダの移動・名前変更など）: 解決先を開く。フォルダが存在すれば、アクセスを開始した後にブックマークを作り直して保存する。
- 解決できない（削除・取り外し）: ブックマークに記録されたパス（`URL.resourceValues(forKeys:fromBookmarkData:)` の `.pathKey`）を開き、利用不可の状態を表示する。元のブックマークは書き換えない。作り直すとセキュリティスコープ付きの情報を失い、ディスクが戻った次回の起動で解決できなくなる。

フォルダを移動すると、解決結果は移動先を指し、`bookmarkDataIsStale` が `true` になる。削除すると解決はエラー（Cocoa 4）になるが、記録されたパスは取り出せる。どちらも2026-10-08に確認した。

## 検証

`WorkspaceFileIndexTests` で次を確認する。

- 存在しないルート、ファイル、`chmod 000` のフォルダで `scan` が理由付きのエラーを投げること。読めないサブフォルダはエラーにせず、空のフォルダとして数えること。
- 権限を失ったルートと削除したルートで、ストアが `rootURL` を保持したまま利用不可の状態になり、一覧を空にすること。読めるようになった後の更新で状態が消え、一覧が戻ること。
- 移動したフォルダの古いブックマークで、移動先を開き、作り直したブックマークが古くないこと。
- 削除したフォルダのブックマークで、記録されたパスを利用不可として開き、ブックマークを残すこと。フォルダを作り直すと一覧に戻ること。
- フォルダ全体の検索と添付ファイルの確認が、空の結果ではなくエラーを返すこと。

サンドボックスの権限失効は単体テストで再現できないため、`chmod 000` による権限エラーで代替している。

## 残る制約

- 読めないサブフォルダの中の書類はリンク更新の対象にならない。移動計画（`planMove`）はサブフォルダの読み込み失敗を数えていないため、そのフォルダ内のリンクは更新されない可能性がある。
- `FilePathCompletion.scan` は、現在の書類のフォルダを読めない場合に空の候補を返す。補完候補が出ないだけで誤った結果を示さないため、変更していない。
