# 明示スナップショットの保存先と改名・移動

明示スナップショット（「スナップショット履歴」シート）は、書類ごとに Application Support の `MKTownEditor/Snapshots/<ダイジェスト>/` へ保存する。ダイジェストは書類のパスの SHA-256 で、フォルダには索引 `index.json` と、スナップショットごとの内容ファイル `<UUID>.md` を置く。実装は `Sources/MKTownEditor/WorkspaceSnapshotHistory.swift` の `WorkspaceSnapshotStore`。

## 不具合: 改名・移動で履歴が見えなくなる（Issue #35）

保存先が書類のパスで決まるため、書類を改名・移動すると新しいパスのフォルダには履歴がなく、履歴シートは空になっていた。ピン・ブックマーク・名前付きレイアウトは改名・移動時にパスを付け替えていたが、スナップショットには付け替えの処理がなかった。旧パスのフォルダは削除する処理もないまま Application Support に残り、書類を元の名前に戻すと履歴が復活する状態だった。

## 設計

### 書類のパスの決め方

`WorkspaceSnapshotStore.documentPath(for:)` で書類のパスを正規化してからダイジェストを求める。存在する書類はシンボリックリンクを解決したパスを使う（以前と同じ値になるので、既存の保存先はそのまま使える）。存在しないパスは、存在する親フォルダまで遡って解決し、残りの名前を付け足す。

存在しないパスを `URL.resolvingSymlinksInPath()` にそのまま渡すと、リンクを解決できない。たとえば `/private/tmp/a.md` は、ファイルがあれば `/tmp/a.md` に解決されるが、なければ `/private/tmp/a.md` のまま返る。改名後の旧パスは存在しないので、この差で旧パスのダイジェストが保存時と変わり、履歴を見つけられなくなる。親フォルダから解決すれば、移動の前後で同じパスになる。

### 索引の形式

`index.json` は `{"documentPath": "...", "entries": [...]}` の形式で書く。以前の形式（項目の配列だけ）も読み込める。以前の形式の索引は、次のいずれかの時点で書類のパスを書き加える。

- その書類の履歴シートを開いたとき（`recordDocumentPath(for:)`）
- スナップショットを保存・削除したとき
- 改名・移動で履歴を移したとき

以前のバージョンのアプリは新しい形式の索引を読めない。

### 改名・移動時の付け替え

`remap(from:to:)` は、書類を移動した後に呼び、旧パスのフォルダを新しいパスのフォルダへ移す。フォルダを移動した場合は、次の二つの方法で配下の書類の履歴を探して移す。

- 索引に記録した `documentPath` が旧フォルダの配下にある履歴。削除済みの書類の履歴も、フォルダと一緒に移る。
- 移動後のフォルダ配下にある各ファイルについて、移動前のパスを逆算して求めた保存先。パスを記録していない以前の形式の履歴は、この方法でしか見つからない。

移動先のパスに既に履歴がある場合（以前に同じ名前の書類があった場合）は、両方の項目を残して統合する。1件の移動に失敗しても残りの履歴の移動は続け、最後に最初の失敗を報告する。

呼び出し元は次の二つ。

- ワークスペースの「名前を変更…」「移動…」（`WorkspaceFileOperationSheet.apply`）。ピン・ブックマーク・名前付きレイアウトの付け替えと並べて呼ぶ。ファイルの移動は完了しているので、履歴の付け替えに失敗しても操作全体は失敗扱いにしない。
- 書類ウインドウのタイトルバーでの改名・移動や、Finder での移動による `fileURL` の変化（`EditorWorkspace` の `onChange(of: fileURL)`）。`remapMovedDocument(from:to:)` が背景で付け替える。旧パスに書類が残っている場合は別名で保存したものとみなし、履歴を元の書類に残す。

ゴミ箱へ移動した書類の履歴は削除しない。「元に戻す」で書類を戻すと、履歴も再び表示される。

### 書類が見つからない履歴の整理

履歴シートの「書類が見つからないスナップショットを整理…」で、元の書類が存在しない履歴を一覧して削除できる（`WorkspaceSnapshotCleanupSheet`）。一覧は `orphans()` が保存先のフォルダをすべて読んで作る。履歴シートを開くたびに全フォルダを読むのを避けるため、一覧は整理シートを開いたときにだけ作る。

- 索引に記録したパスに書類がないものは「元の書類が見つからない」に並べ、個別にも、まとめても削除できる。
- パスを記録していない以前の形式の履歴は、書類の有無を判定できないため「元の書類が不明」に分けて並べ、個別にだけ削除できる。書類が残っている場合でも、その書類の履歴を一度開くとパスが記録され、この一覧から外れる。
- 削除の直前に書類の有無をもう一度確認し、一覧を作った後に書類が戻った履歴は削除しない（`deleteOrphan(_:)` が false を返す）。

## 検証

`WorkspaceSnapshotHistoryTests` で次を確認する。

- `testHistoryFollowsRenamedDocumentAndLeavesNoOldFolder`: `/private` を前置したパスで保存した書類を改名しても、新しいパスで履歴と本文を読め、旧フォルダが残らない。存在しないパスを親フォルダから解決しない実装では失敗する。
- `testFolderMoveRemapsDescendantsIncludingLegacyIndexes`: フォルダの移動で、配下の書類・削除済みの書類・以前の形式の索引の履歴が移り、同じ接頭辞を持つフォルダ外の書類の履歴は動かない。
- `testDocumentWindowMoveRemapsOnlyWhenOldDocumentIsGone`: 別名で保存した場合は履歴を移さず、改名した場合は移す。
- `testRemapMergesWithHistoryAlreadyAtDestination`: 移動先の既存の履歴と統合する。
- `testLegacyIndexIsReadAndUpgradedWhenHistoryOpens`: 以前の形式の索引を読め、パスを記録すると書類のある履歴として扱われる。
- `testOrphansListMissingDocumentsAndDeletionSkipsRestoredOnes`: 書類が見つからない履歴の一覧と削除、一覧の作成後に書類が戻った場合に削除しないこと。

## 同じ原因の確認

書類のパスをキーにした保存先は、ほかに次がある。

- ブックマーク（`EditorSettingsStore.moveBookmarks`、`moveDocumentState`）、ワークスペースのピン（`WorkspaceViewSettings.remapPins`）、名前付きレイアウト（`WorkspaceNamedLayoutStore.remapDocuments`）は、ワークスペースでの改名・移動と書類ウインドウでの改名・移動の両方で付け替えている。
- 書類ごとの表示状態（表示モード、カーソル位置、執筆セッション）は、書類ウインドウでの改名・移動では `moveDocumentState` で付け替えるが、ワークスペースの「名前を変更…」「移動…」では付け替えていない（2026-10-08 時点、未対応）。
- フォルダごとの設定（`EditorSettingsStore` の `folders`）は、フォルダの改名・移動で付け替えていない（同上）。

## スナップショットと名前付きレイアウトの削除（Issue #37）

スナップショット履歴のコンテキストメニュー「削除」は、索引の項目と内容ファイルを確認なしにメインスレッドで削除していた。作業レイアウトのごみ箱ボタンも1回のクリックで削除していた。どちらも取り消せない。

- 削除の前に `confirmationDialog` で「“名前”を削除しますか？」と確認し、取り消せないことを説明する。削除ボタンには `role: .destructive` を付け、キャンセルは既定の操作に任せる（Apple Human Interface Guidelines の、取り消せない破壊的な操作は確認するという指針に従う）。
- スナップショットの削除は、保存と同じく `Task.detached` で背景で実行し、終わるまで他の操作を無効にする。
- 最後のスナップショットを削除したら、保存先のフォルダごと削除する。内容ファイルが既にない項目も、索引から外せれば削除できたものとして扱う。
- 書類が見つからないスナップショットの整理シートも、個別・まとめての削除の前に同じ形で確認する。

`testBackgroundDeleteRemovesOnlyThatSnapshotAndEmptyFolder` で、背景からの削除が対象の項目だけを消すこと、再削除と内容ファイルを失った項目の削除が失敗しないこと、最後の項目を消すとフォルダが残らないことを確認する。確認ダイアログそのものは UI テストの対象で、ユニットテストでは確認していない。

確認なしで削除する操作は、ほかに次がある（2026-10-08 時点、未対応）。いずれも項目は小さく作り直せるため、この修正では変更していない。

- サイドバーのブックマークのコンテキストメニュー「ブックマークを削除」（`EditorWorkspace`）
- 設定の用語・スニペット・拡張の削除ボタン（`EditorPreferencesView`）。スニペットはユーザーが書いたテンプレートを含むので、確認か取り消しを検討する余地がある。
