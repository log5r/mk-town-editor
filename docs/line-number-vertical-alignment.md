# 行番号のY座標の揺れ

行番号を行の矩形の中央に描くと、改行の追加・削除で数字が上下に動いていた。通常の行の矩形には行間が含まれる一方、末尾の行や末尾の空行には含まれない場合がある。既定の行間3ptでは、同じ1行目の数字が1.5ptずれることをユニットテストで確認した。

`MarkdownLineNumberLayout` は、各行の先頭座標に本文フォントの `defaultLineHeight(for:)` を組み合わせ、数字の位置を求める。通常の行、末尾の空行、空の文書で同じ高さを使う。行の先頭座標はTextKitから取得するため、折り返しやスクロール、行間の設定に合わせて本文を追従する。折りたたみマーカーも同じ高さを使う。

`MarkdownLineNumberRulerTests` の追加テストでは、3種類のフォントと行間0・3・12ptで、空の文書、改行のみの文書、本文、末尾改行の間を行き来しても1行目の数字のY座標が変わらないことを検証する。折り返しと末尾の空行を含む文書では、カーソルを全位置へ移して再レイアウトしても各行番号の位置が変わらないことを確かめる。

関連箇所として、行番号と折りたたみマーカーの描画、空の文書と末尾の空行の生成経路を確認した。`TypewriterScrolling.lineMidY` も行の矩形の中央を使うが、用途はスクロール先の計算で、表示領域の10%以内の差ではスクロールしない。数字の描画位置の補正は行番号のレイアウトに限定する。

## 分割表示のプレビュー更新によるスクロール

分割表示には、本文全体が移動して行番号も揺れる別の経路があった。末尾で改行を増減するとプレビューのブロック位置が変わり、その位置の更新から本文へのスクロール同期が呼ばれていた。行番号の描画位置だけを補正しても、この移動は防げない。

`MarkdownPreview` はブロック位置を `PreviewUserScrollMonitor` に記録し、プレビューの `NSScrollView.didLiveScrollNotification` を受けたときに本文へ通知する。監視用のビューはスクロール内容の背景に置き、対象の `NSScrollView` に接続する。表示位置の更新やコードからのスクロールだけでは本文を動かさない。解析結果が変わったら古い位置を破棄し、新しい解析結果に対応した位置が届くまで同期を待つ。

`MarkdownRulerWorkspaceTests` は実際のワークスペースで改行を20回追加・20回削除し、既存の行番号のY座標と文書内容を確認する。同じテスト群で、プレビューをコードから動かしても本文が移動せず、ユーザーのスクロール通知では選択範囲を保って本文が追従することを確認する。`MarkdownRulerDrawingTests` は行番号の描画結果を比較し、`EditorScrollSyncTests` は通知と位置更新の順序、解析の切り替え、監視の解除を検証する。

監視ファイルを復元するときは、`MarkdownPreview` への接続とXcodeのSourcesへの登録も必要になる。Swift Packageはディレクトリ内のSwiftファイルを自動で対象にするが、Xcodeのアプリターゲットは個別に登録する。`Tools/test_xcode_project.py` は両者の対象ファイルが一致することを検証する。
