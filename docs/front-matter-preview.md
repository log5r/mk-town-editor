# Obsidianプロパティの整形表示

macOS版の「設定」→「プレビュー」で「プレビューにフロントマターを表示」をオンにし、「Obsidianのプロパティを整形して表示」をオンにすると、文書先頭のYAMLを項目名と値の2列で表示する。見出しも含めて文字サイズは標準倍率で12 ptとし、プレビューの拡大率に従って拡大する。通常のプレビューと別ウインドウで同じ設定を使う。

整形の初期値はオフ。整形だけをオフにするとYAMLの原文表示に戻り、「フロントマターを表示」をオフにすると枠全体を隠す。両方の設定はアプリ全体で保存し、表示を隠しても整形設定は保持する。文書の内容は変更しない。Markdown構文を「基本」に設定した場合は、従来どおりフロントマターとして分離しない。

## 対応する値と原文表示

[Obsidianのプロパティ仕様](https://obsidian.md/help/properties)を参照し、単一行の文字列、数値・真偽値・日付の表記、`[a, b]`形式の配列、インデントの有無を問わない箇条書き形式のリストを対象にした。リストの各値は「·」で区切る。項目の順序と値の大文字・小文字を保ち、引用符と値の外側のコメントは整形時に除く。値にはMarkdownの書式やリンクを適用しない。

表示用の解析は一般的なYAMLパーサーの代替にはしない。ネストした構造、ブロック文字列、アンカー、未対応のエスケープ、不完全な値は、その項目のYAMLを等幅文字で表示する。JSON形式のプロパティや引用符付きのキーなど、項目に分割できない形式ではフロントマター全体を原文で表示する。編集用の`FrontMatterProperties`とは解析を分け、表示の対応範囲を広げても編集可能な範囲は変えない。

## 検証

`FrontMatterPropertiesTests`で通常のプロパティ、タグ・別名のリスト、CRLF、引用符・コメント、複雑な値の原文保持を確認する。`FrontMatterPropertiesEditorTests`では実際のSwiftUIビューを配置し、長い値の折り返しと拡大率による高さの変化を確認する。`EditorSettingsTests`で旧設定の読み込み、初期値、再読み込み、表示と整形の独立した保存を確認する。`LocalizationCatalogTests`で設定画面の日本語・英語の文言を検査する。
