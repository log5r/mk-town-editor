# 日本語入力の変換中に文字が消える問題

Google日本語入力で本文に日本語を入力すると、ローマ字を打つたびに変換中の文字が確定されたり消えたりして、日本語を入力できなかった。英数字の直接入力には影響がない。`start.sh` で起動したPackage版だけでなく、`MKTownEditor.xcodeproj` から起動したアプリでも同じ症状を再現したので、起動形態ではなくエディターの実装に原因がある。

## 原因

日本語入力などのインプットメソッドは、変換中の文字列を「マークテキスト」としてテキストビューに置き、確定するまで本文として報告しない。そのため、変換中は `NSTextView` の内容(マークテキストを含む)と、SwiftUI側のバインディングの本文(マークテキストを含まない)が一致しない。

`MarkdownTextEditor` の `updateNSView` は、テキストビューの内容とバインディングの本文が異なると、バインディングの本文でテキストビューを置き換えていた。変換中にSwiftUIの再描画が起きると(選択範囲の公開など、エディターモデルの状態変化で頻繁に起きる)、この置き換えが走って変換中の文字列を破棄する。AppKitは変換が途切れたことをインプットメソッドに伝え、インプットメソッドはその時点の文字列を確定する(`commitComposition:`)。確定した文字列もその後の再描画で再び古い本文に戻され、結果として本文からは消える。

2026-10-08の調査では、`log show` でGoogle日本語入力(`GoogleJapaneseInput` プロセス)の記録を見ると、ユーザーがキーを押すたびに `Setting marked text` の直後に `Inserting text`(確定)と空のマークテキスト設定が記録されていた。スクリプトで「nihongo」を素早く入力した場合は7回の `Setting marked text` の後に一度だけ確定が起き、本文には何も残らなかった。再描画が入るタイミングで確定が起きることと一致する。

## 修正

`updateNSView` では、テキストビューにマークテキストがある間はバインディングからの置き換えを行わない。変換が確定すると `insertText` から `textDidChange` が呼ばれ、確定した本文がバインディングへ反映される。共同編集などの外部更新は、もともと変換中は保留し、マークテキストが消えた時点で再適用する仕組みになっている。

## 検証

- `EditorCompositionTests.testReRenderDuringCompositionKeepsMarkedText` で、エディターを `NSHostingView` に載せ、`setMarkedText` の後に監視オブジェクトの変更通知で再描画を起こしても、マークテキストと変換中の文字列が保持され、`insertText` で確定した本文がバインディングへ届くことを確認する。修正前はこのテストが失敗する(本文が空になる)。
- 実機では、`./start.sh` で起動したアプリにGoogle日本語入力で「nihongo」と入力し、変換候補の表示とReturnによる確定で本文に「にほんご」が残ることを確認する。本資料では、`osascript` の `System Events` で同じ操作を自動化し、アクセシビリティの `AXTextArea` の値を読み取って確認した。

## 関連

- インプットメソッドが接続できていても文字が入力できない場合は、まず [`swift run` で起動したときに文字が入力できない問題](package-launch-activation.md) のactivation policyを確認する。
