# 設計判断

## 方針

CodiMD の特徴のうち、Markdown ソースとレンダリング結果を同時に確認できる編集体験を採用した。サーバー、アカウント、リアルタイム共同編集は本アプリのローカル書類モデルとは責務が異なるため、初期版には含めない。

## macOS 標準コンポーネント

- `DocumentGroup` と `FileDocument` で「新規」「開く」「保存」「別名で保存」と自動保存をシステムに委ねる。
- `NSTextView` と `NSScrollView` で、Undo、検索バー、スペルチェック、キーボード操作、アクセシビリティを提供する。
- `HSplitView` で編集領域とプレビュー領域の幅をユーザーが調整できるようにする。
- `ToolbarItem` とセグメント形式の `Picker` で表示モードを切り替える。
- SF Symbols とセマンティックカラーを使用し、ライト／ダークモードに追従する。

## Markdown 処理

プレビューは文書全体の `MarkdownAnalysis` からブロックを取得し、Foundation の `AttributedString` Markdown パーサーでインライン要素を処理して `NSAttributedString` に変換する。各ブロックは原文のUTF-16範囲、親ブロック、コード言語を保持する。見出し、引用、リスト、コードブロックには AppKit の標準フォント、色、段落スタイルを付ける。Web コンテンツや独自 HTML を埋め込まないため、表示がシステムの文字設定とアクセシビリティに自然に追従する。

現在の `MarkdownAnalysis` は既存表示の構文を対象とする位置付き基盤であり、CommonMarkやGFMの完全な解析器ではない。複数行段落、複数段落のリスト、参照リンク、表などの解釈は個別の構文項目で追加する。表示は当面ソース順にブロックを描画し、親子関係に応じたインデントや装飾もそれぞれの項目で追加する。

書式入力は純粋関数 `MarkdownFormatter` として分離し、UTF-16 ベースの `NSRange` を扱う。これにより `NSTextView` の選択範囲と日本語入力を安全に接続し、UI を起動せず単体テストできる。

書式コマンドは置換対象の `NSRange`、置換文字列、変更後の選択を計画する。`NSTextView` には対象範囲だけを通知して `NSTextStorage` を更新する。全文を `string` に代入すると Undo 履歴が失われるため、書式操作では行わない。IME の未確定文字列がある間と編集が拒否された場合は変更しない。Undo の結合は AppKit のイベント境界に従い、別イベントで実行したコマンドが個別に戻ることをテストする。

解析器が返す位置は1始まりの行・UTF-8バイト列、AppKitの選択位置はUTF-16単位として `MarkdownPositionMap` で相互変換する。Unicodeスカラーの途中を指す位置は拒否する。CRLFは1つの改行として扱い、次行の開始位置はLFの直後とする。結合文字のスカラー境界は保持する。

編集セッションの選択範囲・スクロール位置・フォーカス復帰の意図は、書類画面ごとの `MarkdownEditorModel` が保持する。表示切替で `NSTextView` が破棄される際は参照を解除し、新しいビューの接続時に状態を復元する。外部更新などで本文が短くなった場合は選択範囲を本文内へ収める。フォーカスはビューがウインドウへ接続された後に復元する。

見出しレベルはメニューからH1〜H6と本文を選べる。既存のATX見出し記号と末尾の閉じ記号を取り除いて対象行だけを書き換える。本文行を本文に変換するなど、変更内容が同じ場合は編集通知やUndo項目を作らない。

`DocumentGroup` の構成から渡される `fileURL` を書類画面の `DocumentContext` に反映する。未保存書類では相対リソースを解決せず、保存・移動・別名保存でURLが更新されるたびに基準ディレクトリも変わる。書類本文の読み書きは引き続き `FileDocument` に任せ、URLから本文を再読込しない。参照: [Apple DocumentGroup](https://developer.apple.com/documentation/SwiftUI/DocumentGroup)。

設定は `EditorSettingsStore` で本文と分離して保存する。表示モードは書類ごとの値、最も近い親フォルダの指定、アプリ共通の既定値の順に解決する。フォントサイズもフォルダ指定からアプリ共通値へフォールバックする。以前の `SceneStorage` の表示モードは、書類ごとの設定が未登録のときに限り一度取り込む。未保存書類の表示モードはその画面内に保持し、保存時に書類の設定へ移す。

書式・検索の操作名、ショートカット、実行処理は `EditorCommand` に集約する。メニュー、ツールバー、右クリックメニューはこの定義を使い、編集ビューがない場合や編集不可・IME変換中は無効化する。実行時にはその画面の `MarkdownEditorModel` を渡し、別ウインドウの書類を変更しない。

連続した通常行は1つの段落ブロックとし、行間の改行を `MarkdownLineBreak` の通常・明示に分けて保持する。末尾の2個以上の空白またはエスケープされていないバックスラッシュは明示改行として描画し、通常改行は空白として描画する。原文範囲には改行記号と書式記号をそのまま残す。

リスト項目は元のインデントと親項目を解析結果に保持する。同じ項目内の直後の行は1つ目の段落へ続け、空行の後で字下げされた段落はその項目の子ブロックにする。番号付きと箇条書きの混在を許し、プレビューでは深さに応じた段落インデントを付ける。

連続する引用行は1つの引用ブロックにまとめ、引用記号を1段取り除いた行を既存のブロック解析に再帰的に渡す。これにより引用内の複数段落、リスト、フェンスコード、入れ子の引用を同じ構文木から描画する。子ブロックの原文範囲は引用記号を含む元の行のUTF-16範囲を保持する。段落の直後に限り、引用記号のない次行を遅延継続として取り込む。空行、リスト、フェンスコードの後では引用を終える。

コードブロックはバッククォートとチルダのフェンスを区別し、開始フェンスの文字・長さ・言語名を解析結果に残す。閉じフェンスは同じ文字で開始フェンス以上の長さを要求し、最大3スペースの字下げを許す。4スペース以上の字下げはインデントコードとして扱い、内部の空行と追加の字下げを本文に残す。リスト項目内では項目本文の開始位置からさらに4列以上の字下げを子コードブロックとする。通常段落の途中でインデントコードを開始しない。構文規則の参照: [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/#indented-code-blocks)、[フェンスコード](https://spec.commonmark.org/0.31.2/#fenced-code-blocks)。

Setext見出しは、直前に連続する段落行がある場合だけ`=`または`-`の下線を見出し記号として消費する。これにより`本文\n---`はH2、単独の`---`は区切り線になる。ATX見出しは最大3スペースの字下げ、空見出し、前に空白がある末尾の閉じ記号に対応する。区切り線は同じ記号3個以上で、記号間の空白・タブを許す。原文の範囲には見出し記号や下線を含める。構文規則の参照: [CommonMarkの見出しと区切り線](https://spec.commonmark.org/0.31.2/#thematic-breaks)。

GFM表はヘッダーと区切り行の列数が一致する場合だけ表ブロックにする。区切り行のコロンから列揃えを決め、本文行の不足列は空セルで補い、余分な列は無視する。エスケープされていない`|`を列区切りとし、引用・リスト内でも親ブロックと原文のUTF-16範囲を保持する。表を含むプレビューは縦スクロール領域内に各表専用の横スクロール領域を置く。セル内のインラインMarkdownは既存のパーサーで表示し、見出しとセルの内容には読み上げラベルを付ける。仕様の参照: [GFM Tables](https://github.github.com/gfm/#tables-extension-)。

GFMの`[ ]`・`[x]`・`[X]`はリスト項目の最初の段落の先頭だけでタスク状態として認識する。原文と選択用のUTF-16範囲を変えず、表示時に記号を「☐ 未完了」「☑ 完了」へ置き換える。プレビューはテキストとしてキーボード選択でき、状態名を文字で含むため読み上げ時も区別できる。チェック操作による本文変更は表示機能とは別の編集コマンドとして扱う。仕様の参照: [GFM Task list items](https://github.github.com/gfm/#task-list-items-extension-)。

取り消し線の調査では、FoundationのMarkdownパーサーが`~~文字~~`をインライン意図として解析する一方、`NSAttributedString`への変換結果では意図属性の値が`NSNumber`になり、従来の`InlinePresentationIntent`への直接キャストで取り出せないことが分かった。数値から意図を復元し、取り消し線には`strikethroughStyle`を適用する。同じ経路を通る太字・斜体・インラインコードも回帰テストで確認する。取り消し線の構文は[GFM Strikethrough](https://github.github.com/gfm/#strikethrough-extension-)に従う。

参照形式のリンク・画像は、ブロック解析中に文書全体の定義を先に集め、最初の定義を採用する。ラベルは前後や連続する空白を正規化して小文字化し、通常の`[文字][ラベル]`、`[ラベル][]`、`[ラベル]`を解決する。定義行はプレビューから除き、原文のUTF-16範囲を参照情報に保存する。引用・リスト・表セルでも共通の定義を使う。インラインコード内やエスケープした構文は置換しない。画像参照は画像表示機能の追加前は「画像: 代替テキスト」という参照先へのリンクで示す。仕様の参照: [CommonMark Link reference definitions](https://spec.commonmark.org/0.31.2/#link-reference-definitions)。

太字・斜体・インラインコードのコマンドは同じ範囲で再実行すると記号を外す。カーソルが書式の内側にある場合もその書式を解除し、カーソルが記号の外側にある場合は新しい書式を挿入する。選択が既存の書式と一部重なる場合は記号を含む範囲まで広げ、未書式の文字を含む選択は単一の書式にまとめる。全体が書式付きなら記号を外す。太字の`**`・`__`、斜体の`_`・`*`、長さの異なるバッククォートを対象とし、エスケープした記号やコードスパン内の記号を既存の書式と誤認しない。コードスパンの検出は参照リンク処理とも共有する。変更範囲とカーソル位置はUTF-16で管理し、Undoは従来の編集モデルに委ねる。

取り消し線の挿入は書式トグルの共通処理を使う。選択範囲を`~~`で囲み、空選択には選択済みの「取り消し線」を入れる。再実行では同じ規則で解除する。メニューと右クリックメニューから使え、ショートカットはCommand＋Shift＋Xとする。既存のGFMプレビューが挿入結果を表示する。

番号付きリストの挿入は選択された各行をUTF-16の行範囲で処理する。箇条書き・既存の番号記号を外し、最初の項目が番号付きなら開始番号を維持して連番を振る。字下げと改行形式は保持し、空行は項目化しない。空文書や空行にカーソルがある場合は`1. `を入れて記号の後ろにカーソルを置く。コマンドはMarkdownメニューと右クリックメニューから実行できる。

タスクリストの挿入は番号付き・箇条書きと同じ行解析を使う。選択した各項目を`- [ ] `に変換し、既存の`[x]`・`[X]`は完了状態を維持する。箇条書きコマンドでタスクのチェック記号を外せる。空行は維持し、空文書や空行のカーソルでは記号の後ろへ挿入位置を移す。番号付きリストへ変換する際は既存タスク状態を本文に残す。リストの記号変換は原文の行末形式と字下げを保つ。

タスクの完了切替は解析済みタスク項目の原文行だけを対象とし、コードブロック内にある同じ文字列は変更しない。カーソル行ではその項目を切り替え、複数選択では全項目が完了なら未完了へ、それ以外なら完了へ揃える。状態の1文字だけを置換するため本文の長さ・選択位置・行末形式は変わらない。編集画面とプレビューのチェックボックスは同じ`MarkdownFormatter.toggleTasks`を使い、編集画面では`NSTextView`のUndo、プレビュー専用表示では文書の`UndoManager`に変更を登録する。チェックボックスには項目名を含む読み上げラベルを付ける。

コードブロック挿入は、選択範囲にある連続バッククォートの最大長より1文字以上長く、最短3文字のフェンスを使う。選択した内容はそのままフェンス内に残し、空選択では空のコード行にカーソルを置く。選択が行の途中にある場合は前後に改行を追加してフェンスを独立した行にする。既存文書がCRLFなら挿入する改行もCRLFに合わせる。言語はメニューと右クリックメニューで「言語なし」、Swift、JavaScript、TypeScript、Python、JSON、Bash、Markdownから選ぶ。言語名は固定した識別子を出力し、任意の未検証文字列をフェンスの情報文字列に入れない。

区切り線の挿入には`***`を使い、文書冒頭でもYAMLフロントマターと重ならないようにする。選択範囲がある場合はその文字列を置き換え、前後に既存の空行を数えて必要な改行だけを追加する。行の途中なら本文を分け、区切り線の前後を空行で区切る。これにより直前の段落をSetext見出しとして解釈させない。改行形式は既存文書に合わせ、挿入後のカーソルは区切り線の後ろへ置く。

リンクコマンドは書類ごとの編集モデルからシートを開き、表示名・URL・任意のタイトルを編集する。カーソルが既存のインラインリンク内にある場合は表示名・URL・タイトルを読み込み、保存時にリンク全体を置き換える。URL中の空白・制御文字・山括弧は百分率符号化し、丸括弧とバックスラッシュはMarkdownのバックスラッシュでエスケープする。タイトルの引用符とバックスラッシュ、表示名の角括弧も共通の構文処理でエスケープする。既存の装飾付き表示名を変更しない場合は原文の記号を残す。シートを開いてから本文が変わった場合は古い位置への書き込みを拒否する。編集は従来の`NSTextView`経路を通してUndo可能にする。構文規則の参照: [CommonMark Links](https://spec.commonmark.org/0.31.2/#links)。

画像挿入シートはURLとファイルを選択でき、代替テキストを必須、タイトルを任意とする。画像構文はリンクと同じURL・タイトルのエスケープ処理を使う。文書内にある画像ファイルは相対パスで参照し、文書外のファイルは文書横の`assets`へコピーする。保存名が重なる場合は連番を付け、画像形式は拡張子とImageIOの内容判定で確認する。`assets`が文書外へのシンボリックリンクならコピーを拒否する。ファイルコピーは別タスクで行い、本文変更などで挿入できなかった場合は今回作成したファイルを削除する。未保存文書ではファイル選択を使えず、保存後に挿入する。相対パスの解決は`DocumentContext`を使い、後続のローカル画像表示・ドラッグ＆ドロップ・貼り付けも同じ`ImageResourceManager`を使えるようにする。

編集画面のMarkdown構文色分けは`NSTextStorage`を書き換えず、`NSLayoutManager`の一時的な文字色属性を使う。ブロックの見出し・コード・区切り線・表は`MarkdownAnalysis`の原文範囲から求め、引用・リスト・タスクの記号とインラインコード・リンク・強調記号をUTF-16範囲で補う。コードブロックとコードスパン内の他の構文は装飾しない。入力と外部更新の後に再適用し、IME未確定文字列がある間は更新しない。表示のみの処理なのでUndo履歴と原文は変えない。大きい文書向けの差分解析・再描画はB07で検討する。

行番号は`NSScrollView`の縦`NSRulerView`に表示し、本文の保存内容には含めない。`NSLayoutManager`の行フラグメントから画面上の位置を得て、各フラグメントの先頭が原文の論理行頭である場合だけ番号を描く。これにより折り返し行で番号が重複しない。空文書と末尾改行後の空行も1行として表示し、CRLFを1つの行区切りとして数える。入力・外部更新・スクロールでガターを再描画し、桁数に応じて幅を変える。TextKitの行フラグメント列挙と`NSRulerView`の描画・幅変更はAppleの[NSLayoutManager](https://developer.apple.com/documentation/appkit/nslayoutmanager/enumeratelinefragments(forGlyphRange:using:))と[NSRulerView](https://developer.apple.com/documentation/appkit/nsrulerview)を使用する。

Returnキーでのリスト・引用継続は`NSTextView.insertNewline`から編集モデルへ渡し、通常の範囲編集とUndo経路を使う。箇条書きは同じ記号、番号付きリストは番号を1増やして区切り記号を保持し、タスクは未完了`[ ]`で継続する。引用は元の階層を引き継ぐ。空のリスト項目ではリスト記号を外し、引用内なら引用階層を残す。空の引用行では最も内側の引用記号を1つ外す。コードブロック内、選択範囲あり、IME未確定中は補助せず標準の入力処理に委ねる。編集が拒否された場合も別の改行を挿入しない。原文の改行形式はCRLF・CR・LFを維持する。

リストのTab／Shift-TabとMarkdownメニュー・右クリックメニューは同じ`MarkdownIndentation`を使う。選択されたリスト項目の行と解析器が示す子ブロックの行をまとめて2スペース移動し、引用内では`>`の後にスペースを出し入れする。空行と選択外の兄弟項目は変えず、最上位の項目をアウトデントした際に子だけを動かさない。コードブロックでは通常の字下げとして4スペースを扱い、カーソルだけのTabはその位置に挿入する。変更は1つのUTF-16範囲編集にまとめ、Undoと選択位置の変換を既存のモデルに委ねる。通常の段落はAppKitのTab処理に任せる。

記号の自動補完は`NSTextView.insertText`で1文字の入力を受けたときに実行し、`()`・`[]`・`{}`・バッククォート・`*`・`_`を対にする。選択文字列は対の内側へ残し、選択も内側へ移す。選択中にバッククォートが含まれる場合は、内部の連続数より長い記号を使う。奇数個のバックスラッシュ直後は補完せず、コードブロックとコードスパン内ではMarkdownの強調記号・バッククォートを補完しない。括弧はコード内でも補完する。IMEの置換範囲指定中と未確定文字列がある間はAppKitの入力へ委ねる。補完も既存の範囲編集を通してUndo可能にし、編集拒否時は別の文字を挿入しない。

表挿入はメニュー・右クリックからシートを開き、データ行数1〜20、列数1〜12を指定する。`列1`から始まる見出し、GFM区切り行、空のデータ行を原文へ挿入し、先頭の見出しセルを選択する。表の前後に必要な空行を追加して隣接段落と分け、CRLF・CR・LFを維持する。シートを開いた後に本文が変わった場合は古い選択位置への挿入を拒否する。列揃えと既存表の行列編集はT02・T03で扱う。

ローカル画像のプレビューはMarkdownパーサーの[画像URL属性](https://developer.apple.com/documentation/foundation/nsattributedstring/key/imageurl)を読み、`DocumentContext`から相対パスを文書の場所に解決する。参照形式の画像も通常の画像構文へ解決して同じ経路を通す。ImageIOで最大960ピクセルのサムネイルを作り、表示は最大480×320ポイントとしたうえで、[TextKitの添付レイアウト](https://developer.apple.com/documentation/appkit/nstextattachmentcontainer)が実際の行幅へさらに縮小する。画像と添付文字に代替説明を付ける。未保存文書・画像が見つからない場合・URL画像は「画像: 代替テキスト」のリンクで表示し、URL画像の自動ダウンロードは行わない。画像の読み込みは現状同期であり、大きな文書の処理はB07の非同期表示と合わせて見直す。

画像ファイルのドラッグ＆ドロップは`EditorTextView`が画像形式のファイルURLを1つだけ受け、TextKitでマウス位置をUTF-16の挿入位置に変換する。ドラッグ中はアクセント色の挿入線を描き、取消時は元の選択範囲へ戻す。Markdownメニューの「画像ドロップ」で、外部ファイルを`assets`へコピーするか元ファイルへの相対パスにするかを選ぶ。文書内のファイルはどちらの設定でもそのまま相対参照する。設定はアプリ共通を保存し、フォルダ設定があればそれを優先する。コピー時は既存の`ImageResourceManager`を使用し、本文や書類URLが非同期処理中に変われば挿入を拒否して作成ファイルを削除する。編集とUndoは既存の範囲編集経路を使い、ドロップにより挿入する代替テキストはファイル名から拡張子を除いたものとする。

標準の貼り付け操作は、ペーストボードにPNGまたはTIFF画像データがある場合だけ画像処理へ進み、通常のテキストではAppKitの貼り付けを使う。画像はImageIOで検証・PNG化して`assets/screenshot-年月日-時分秒.png`へ保存し、同秒の衝突には連番を付ける。選択文字列を画像構文で置き換え、代替テキストは「スクリーンショット」とする。本文や書類URLが変わった場合は挿入せず、今回作成したPNGを削除する。未保存文書では保存先が必要なため標準の保存操作へ案内し、保存後に再度貼り付ける。保存前に画像データを一時保管して後日の保存時に意図せず挿入することは避ける。

管理フォルダは文書横の`assets`に固定し、文書外を指すシンボリックリンクなら保存しない。ファイル取り込みではいったん`assets`内の隠し一時ファイルへコピーし、内容が既存の通常画像ファイルと同一ならその相対パスを再利用する。違う内容で同名なら`-2`以降を付ける。スクリーンショットの貼り付けは各操作を別添付として連番保存する。一時ファイルから最終名への移動後にだけ本文へ画像構文を挿入するため、コピー・PNG化・移動の失敗では本文を変えず一時ファイルを消す。挿入が拒否された場合はその操作で新規作成したファイルのみ削除し、既存の再利用ファイルは残す。`FileDocument`の後続の自動保存が失敗した場合は画像ファイルを保持し、未保存の本文から再保存できるようにする。不要になった添付の自動削除は、他文書からの参照を識別できるワークスペース索引を導入するまで行わない。

編集文字のフォント・サイズ・行間・余白はアプリ共通設定で管理する。フォントサイズには既存のフォルダ別設定を優先し、文字表示メニューの拡大・縮小はアプリ共通サイズだけを変える。フォント種類はサイズ操作とは独立させ、設定画面で選択する。`NSTextView`の既定段落スタイルとインセットに表示設定を適用し、本文文字列やUndo履歴は変更しない。以前の保存データに新しい項目がない場合はシステム等幅フォント、左右・上下18ポイントを使う。

折り返し設定は`NSTextView`の横方向のサイズ変更、テキストコンテナの幅追従、水平スクローラを一緒に切り替える。折り返さないときはレイアウト済み文字の幅から文書ビューの幅を更新し、長い行の末尾までスクロールできるようにする。表示幅は入力・外部更新・ウインドウ幅変更でも更新する。タブ表示幅は選択したフォントの空白幅を基準に段落スタイルへ設定する。リストとコードの字下げ幅は別設定とし、編集コマンドの範囲編集へ渡す。以前の保存データでは折り返し有効、タブ4文字、リスト2文字、コード4文字を既定とする。長い行の幅が変わらない不具合を再現テストに固定した。

見出し・表・タスクを含むプレビューは構造ごとのSwiftUI要素を使う。見出しにはヘッダー特性とレベルを含む読み上げ名、表セルには列見出しと行番号、タスクには内容を含むチェックボックス名を付ける。リンクはレンダラーが付けるURL属性を保持する。装飾用の引用線はアクセシビリティツリーから除く。構造付きプレビューはキーボードのフォーカス対象とし、タスクのチェックボックスへも移動できる。編集ビューの再作成時には既存の編集セッションのフォーカス復帰処理を使う。通常の段落だけの文書は従来の選択可能な`NSTextView`プレビューを維持する。見出し等がある場合の選択操作とVoiceOverの読み上げ順序は実機でも確認する必要がある。参照: [Apple SwiftUIのヘッダー特性](https://developer.apple.com/documentation/swiftui/accessibilitytraits/isheader)、[アクセシブルな移動](https://developer.apple.com/documentation/swiftui/accessible-navigation)。

文書画面ごとに`DocumentAnalysisStore`を持ち、変更された本文の不変スナップショットから構文木・統計・構文色分け範囲を一度に作る。解析はメインスレッド外のタスクで実行し、結果だけをMainActorで公開する。更新ごとに世代番号を進め、遅れて完了した古い結果を捨てる。同一本文の重複要求はまとめる。本文が公開済みの内容へ戻った場合も処理中の別版を無効にする。解析中は直前のプレビューを表示し、古い原文位置を使うタスク操作は無効にする。初回は解析完了まで進行表示にする。AppKitの一時表示属性とプレビュー描画はMainActorで行い、IME未確定範囲の装飾は従来どおり避ける。書式コマンドの候補判定など利用者が明示した操作時の解析は独立したままにし、入力ごとの再解析を集約する。

アウトラインは解析済みの見出しブロックを原文順に並べ、見出しレベルで字下げする。サイドバーはmacOS標準の`NavigationSplitView`を使い、ツールバーから表示を切り替える。選択時は見出しのUTF-16開始位置へ編集カーソルを移し、プレビューの対応ブロックIDをスクロール先にする。プレビュー専用表示では次に編集ビューが接続されたときに選択とスクロールを復元する。古い解析結果の位置へ移動しないように、編集中で解析結果が古い間はアウトラインの選択を無効にする。表示対象の見出しが消えたときは新しい解析結果の見出し一覧へ更新する。

現在のセクションはカーソル位置以前に現れる最後の見出しとする。最初の見出しより前には現在セクションを付けず、同名見出しは表示名ではなくブロックIDで区別する。解析結果が編集中の本文に追いついているときだけサイドバーの該当行を強調し、読み上げにも選択状態を渡す。

指定行への移動はUTF-16の行頭索引を作って行番号を位置に変換する。CRLFを1つの改行として数え、CRとLF単独、末尾改行後の空行も扱う。1未満または最終行を超える番号は有効な範囲へ補正し、シートにもその規則を示す。プレビュー専用表示からは編集表示へ切り替えた後にカーソルを目的行へ移し、再生成される編集ビューが接続された時点でスクロールする。通常の文字入力とUndo履歴は変えない。

見出しのクイック検索は共有アウトラインの項目を対象とし、利用者の入力を前後空白を除いてローカライズされた部分一致で絞り込む。同名見出しも別位置として残す。検索欄からReturnで先頭候補へ、Tabで一覧へ移って矢印キーで候補を選んでから移動ボタンで確定できる。解析が古い間は古い位置へ移動しないよう候補を表示しない。移動処理はサイドバーと同じ経路を使う。

ナビゲーション履歴は書類URLとUTF-16位置の組を保存する。アウトライン・見出し検索・指定行・プレビューから原文への明示的な移動で出発点を積み、通常の文字入力やカーソル移動では履歴を増やさない。戻る操作時の現在位置を進む側へ積み、新しい移動で進む履歴を消す。履歴は画面ごとに最大100件とし、Undo履歴とは分ける。未保存書類の初回保存や別名保存では履歴内の書類URLを新しいURLへ移す。現在のUIで利用できる戻る・進むは同じ書類内の移動を対象とする。書類間の履歴復帰にはアプリ共通の履歴管理が必要となる。

文書内見出しリンクのIDはGitHubの見出しアンカー規則に合わせる。表示文字列からMarkdown装飾を除いて小文字化し、空白をハイフンへ変え、元からあるハイフンとアンダースコアを残し、その他の空白・句読点・記号を除く。同じIDが先にあれば`-1`から連番を付け、既存の文字列と衝突するときはさらに番号を進める。空になる見出しは`section`を基底IDとする。`#fragment`だけのURLを文書内リンクとして扱い、プレビューのSwiftUIリンクとAppKitテキストリンクの両方を同じ索引へ渡す。見つからなければ案内し、見つかればアウトラインの移動経路を使って履歴・編集カーソル・プレビューの位置を揃える。相対ファイルパス付きリンクはL02で扱う。参照: [GitHubの見出しアンカー規則](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#section-links)、[github-sluggerの実装](https://github.com/Flet/github-slugger/blob/master/index.js)。

相対Markdownリンクは現在書類のフォルダを基準に解決し、`.md`と`.markdown`だけを標準の`openDocument`アクションへ渡す。外部URLはシステムへ渡し、未保存書類には基準フォルダがないため相対リンクを開かない。リンクにフラグメントがあればアプリ共通の一時的な移動要求として保持し、開いた先の書類で解析が現行本文に追いついた後に見出しへ移動する。開く操作が失敗した場合は要求を破棄してエラーを示す。書類間の履歴復帰は現在の履歴モデルが画面ごとであるため未対応で、後続の複数書類ナビゲーション設計で扱う。

ファイルパス補完は現行書類のフォルダだけを走査し、隠しファイル・パッケージの内部・シンボリックリンクを除外する。最多500件を読み取り、入力文字を含む候補を最大8件表示する。候補選択時は人が読める相対パスを入力欄へ置き、保存時に既存のリンク構文処理で空白や括弧をエスケープする。走査はバックグラウンドで実行し、未保存書類では候補を出さず保存を案内する。macOSの`/var`と`/private/var`の表記差で絶対パスの前方一致が失敗するため、ディレクトリ列挙の階層レベルから相対パスを組み立てる。

リンク編集欄に`#`がある場合、現在書類または入力した相対パスのMarkdown書類だけから見出しIDを生成して候補にする。対象ファイルはUTF-8かつ8MB以下に制限し、読み取りと解析はバックグラウンドで行う。現在書類では共有解析スナップショットを使う。編集中の別ウインドウに未保存変更がある場合、対象書類の候補はディスク上の内容に基づく。参照形式リンクは現在書類の定義済みIDから選び、`[表示名][ID]`として差分編集する。未定義IDは候補に出さない。

選択範囲へ`http`・`https`・`mailto` URLを貼り付けた場合は、選択文字列を表示名にしてリンク構文へ差分編集する。選択なし、URL以外、既存リンクの内部、IME変換中は標準の貼り付けへ戻す。画像データがある場合は既存の画像貼り付けを先に扱う。元のURLを挿入したい場合はコンテキストメニューの「URL をそのまま貼り付け」を選べる。リンク生成は既存のエスケープ処理とUndo経路を共有する。

リンク診断は要求された時点の本文スナップショットに対して実行し、結果の原文範囲を保持する。インラインリンク・画像は既存のリンク構文パーサーで取り出し、明示的な参照形式`[表示名][ID]`は参照定義索引と照合する。コードブロックとコードスパンを除き、相対ファイル／画像の存在、現書類と対象Markdown書類の見出しIDを確認する。対象書類は8MB以下のUTF-8だけ解析し、同じ書類への複数リンクは解析結果を再利用する。裸の`[ID]`は通常の角括弧との区別がつかないため欠落判定しない。診断一覧の項目を選ぶと原文位置へ移動する。

分割表示のスクロール同期は原文位置と解析ブロックIDを使い、スクロール率は用いない。原文側は`NSTextView`の可視上端の文字位置をレイアウトから求め、対応ブロックをプレビューの上端へ送る。プレビュー側は各ブロックの可視位置から上端のブロックを選び、原文の対応行を上端へ送る。プログラムから生じた再通知は最後に同期したブロックIDで抑え、カーソル位置やUndo履歴は変えない。画像の読み込み等でプレビューの高さが変わるとジオメトリを再評価する。分割表示のプレビューはこの対応を保つため構造化ビューを使う。

プレビューから原文への移動はブロック単位のコンテキストメニューとアクセシビリティアクションで提供する。解析ブロックの原文`NSRange`をそのまま選択し、プレビュー単独表示では編集表示へ切り替える。編集ビューが再生成される場合も選択範囲とスクロール要求をモデルに保持する。明示的な移動としてナビゲーション履歴へ記録する。プレビュー単独表示でも原文範囲を取得するため構造化ビューを使う。

表示倍率はアプリ設定に編集用とプレビュー用を別々に保存する。初期値100%、範囲50〜200%、操作単位10%とし、既存設定の読み込みでは値がない場合に100%を使う。編集倍率は設定済みのフォントサイズと行間へ掛け、プレビュー倍率は描画済み属性文字列のフォントへ掛ける。書類本文やリンク属性は変えない。表示倍率メニューは現在値を示し、通常のCommand+プラス／マイナス／0を編集用、Optionを加えた組合せをプレビュー用とする。フォントの基準サイズは設定画面から別途変更できる。

コードブロックは解析で保持したフェンスの言語名から、Swift、JavaScript／TypeScript、Python、JSON、シェルの字句色分けを選ぶ。短縮名も解決する。文字列・コメント・キーワード・数値を順にトークン化し、文字列内のコメント記号やキーワードを誤着色しない。対応外の言語は従来どおり等幅の単色表示とする。色はAppKitのシステム色を使い、段落間隔・原文・コード言語名は変えない。完全な構文解析ではなく、補間文字列、複数行文字列、言語固有の複雑な字句は対象外とする。

構造化プレビューは`LazyVStack`で可視付近のブロックを生成する。解析結果は既存の文書スナップショットを使い、描画属性は表示に必要な内容の組でキャッシュする。原文位置やブロックIDが変わっても同じ内容なら再描画せず、見出し・本文・表セル等が変わった項目だけ作り直す。参照定義の行位置は描画結果に影響しないため、定義のURL・タイトルが変わった時だけキャッシュを破棄する。書類URL・倍率が変わった時も破棄し、保存件数は最大4000で抑える。引用の深さは一度作った親ID索引から求める。構造化プレビューが使われない内部のネイティブ表示では、本文・書類URL・倍率が前回と同じなら`setAttributedString`を繰り返さない。

検索・置換は`NSTextView`で有効にした標準検索バーを使う。検索・次／前・置換画面・すべて置換を`NSTextFinder.Action`のタグで`performTextFinderAction`へ渡し、標準の検索条件とUndoを利用する。メニューには置換とすべて置換を明示し、置換画面はOption+Command+Fで開く。IME変換中は一括置換を実行しない。参照: [Apple NSTextFinder](https://developer.apple.com/documentation/appkit/nstextfinder)、[置換画面アクション](https://developer.apple.com/documentation/appkit/nstextfinder/action/showreplaceinterface)。

大文字小文字・単語単位などの検索条件はAppKitの標準検索バーが提供し、条件メタデータは検索用ペーストボードに保持される。[確認記録](find-bar-verification.md)にSDK/APIの根拠と実機確認の残件を記す。

正規表現検索は標準検索バーと区別したシートで扱う。`NSRegularExpression`をバックグラウンドで実行し、UTF-16の一致範囲を一覧と原文移動へ渡す。置換文字列の`$0`・`$1`等は対象一致のキャプチャへ展開し、存在しない番号をエラーにする。ゼロ幅一致も有限個の一致として処理する。すべて置換は最初から最後の一致を覆う範囲を1回の差分編集にまとめ、Undoで元へ戻せるようにする。選択済みの一致は1件置換でその位置を優先し、次を検索では次の一致へ進む。本文が検索開始時から変わった場合やIME変換中は編集を拒否する。

選択範囲内の一括置換は標準検索バーの`replaceAllInSelection`アクションを使う。正規表現シートは開いた時点の選択範囲を固定し、利用者が「選択範囲内」を有効にすると、そのUTF-16範囲だけを検索する。置換に成功したら編集差分だけ範囲の長さを更新する。範囲外の編集では位置を補正し、範囲境界にまたがる編集や本文外になった範囲は無効として扱う。現在のカーソル選択を検索範囲の代わりに再利用しないので、一致箇所へ移動しても検索範囲が変わらない。

表の行・列操作は`MarkdownAnalysis`の表ブロックと原文行範囲を使い、現在のセルをUTF-16位置で特定する。行の追加・削除は対象行だけを差分編集し、列操作は表ブロックの各行を同じ列数へ組み直す。区切り行には新しい列の`---`を入れ、既存の配置指定とエスケープしたパイプを保持する。ヘッダーと区切り行は削除せず、最後の列も削除しない。各操作は`MarkdownEdit`を1回適用するため、Undoで戻せる。

列の配置変更は選択セルの列番号から区切り行の対象セルを求め、左`---`、中央`:---:`、右`---:`へ差分編集する。メニューのPickerは解析済みの現在値を表示し、表の外では無効化する。ヘッダーと他の列の原文は保持する。

表内のTab／Shift-Tabは原文セルのUTF-16範囲を求めて次／前のセル内容を選択する。区切り行は移動対象から外す。最後のセルでTabを押した場合は、設定が有効なら行追加の差分編集を使い、無効なら表の後へカーソルを移す。IME未確定中と表の外では既存のキー操作を優先する。設定はアプリ共通で保存し、既存の設定データでは行追加を既定で有効にする。

表の整形はGFMと同じく未エスケープのパイプを区切りとし、コードスパン内でも未エスケープなら列境界として扱う。セル内容のエスケープは変えず、列ごとの表示幅に合わせて空白と区切り行を整える。日本語と絵文字は等幅フォントでの幅を2として数える。列配置は区切り行のコロンを維持し、整形前の選択セルを整形後も選択する。表の外の本文は変更しない。

TSV・CSV変換はクリップボードのタブを優先して区切り文字を判定し、引用符内の区切り文字・改行と二重引用符を解析する。先頭行をヘッダーにし、短い行には空セルを補う。Markdownで構文になる記号はエスケープし、セル内改行は`<br>`へ変換する。改行を含む場合は変換前にシートで方針を示し、確定時に元の本文と選択範囲が維持されていることを確認する。CSVの引用符が不正な場合は本文を変更しない。

HTML書き出しはプレビューと同じ`MarkdownAnalysis`のブロック構造を使う。見出しIDは既存の見出し索引に合わせ、表の配置やタスク状態もHTMLに反映する。インライン構文はFoundationのMarkdown解析結果からリンク・強調・画像等を変換する。テキストと属性値はHTMLエスケープし、危険なリンクスキームは出力しない。ローカル画像はデータURLへ埋め込み、CSSもHTMLに同梱して単一ファイルとして保存する。

PDF書き出しはHTML書き出しと同じ構造・画像解決結果をAppKitの文字レイアウトに読み込み、A4・48pt余白のPDF印刷操作でページ分割する。保存は標準パネルで場所を選び、変換または印刷に失敗した場合はエラーを表示する。

印刷もPDF書き出しと同じ文字レイアウトと段落単位のページ分割を使う。標準のページ設定で用紙・向きを変更し、印刷設定シートで上下左右の余白と書類名ヘッダー・ページ番号フッターを選ぶ。実際の出力はmacOS標準の印刷パネルに渡す。用紙設定は書類画面ごとに保持し、本文のMarkdownには保存しない。

書式付きコピーはエディタの現在の選択範囲だけを別のMarkdown断片として解析し、HTML・RTF・表示用プレーンテキストを同時にクリップボードへ書く。通常のコピーは原文を保持する。断片内だけでは解決できない参照定義は変換しない。

プレーンテキスト書き出しは共通のブロック解析結果から見出し・段落・引用・リスト・コード・表の内容を抽出する。インラインの装飾はFoundationのMarkdown解析で除去し、リンク先と画像説明を選択に応じて追加する。脚注は`[^id]`形式の定義と参照を対象にし、コードブロック内の同じ文字列は残す。UTF-8の`.txt`へ保存し、元のMarkdownは変更しない。

HTML・PDF書き出しのプリセットは編集表示設定と別のUserDefaultsキーに保存する。本文幅・フォント・文字サイズ・余白・表紙・目次を持ち、標準設定は常に利用できる。HTMLではCSSと見出し索引に反映し、PDFでは余白と文字レイアウトへ渡す。表紙を選んだPDFは本文を次ページから開始する。書き出し時の一時的な設定変更はプリセット保存を押すまで保存しない。

ワークスペースは利用者が選んだフォルダのブックマークを保存し、Markdown・プレーンテキストと代表的な添付を再帰的に索引化する。ファイル一覧はサイドバーのアウトラインと切り替える。Markdownは既存の`DocumentGroup`で開き、添付はシステム既定アプリへ渡す。シンボリックリンク・隠しファイルを除き、深さ16・項目数1万の上限を設ける。外部変更には表示中3秒間隔の再走査で追従し、読み込みはバックグラウンドで行う。

クイックオープンはワークスペースのファイル索引からMarkdown・テキスト書類だけを対象にする。入力語を大文字小文字・アクセントを無視して照合し、連続一致とファイル名一致を優先する。候補は最大50件に絞り、確定後は既存の`DocumentGroup`で開く。

ワークスペース内の作成・改名・移動・ゴミ箱への移動はファイルツリーのコンテキストメニューから行う。改名と移動ではワークスペースの全書類を確認して、移動対象を指すインラインリンク・画像リンク・参照定義、および移動する書類自身の相対リンクを更新する計画を先に表示する。適用前に書類の追加・削除と内容変更を再検査し、複数ウインドウの開いている対象書類は操作を止める。書き換え途中の失敗では元データと移動元へ戻す。ゴミ箱移動では影響を受けるリンク数を示し、リンクは残す。パス比較はシンボリックリンクを解決し、`/var`と`/private/var`のような別表記で更新漏れが起きないようにする。

ファイル一覧のピン留め、名前順・更新日時順、書類・添付・拡張子のフィルターは、ワークスペースのルート別にUserDefaultsへ保存する。拡張子候補は索引に現存するファイルから作る。フィルターは表示にだけ適用し、検索やリンク更新に使う元の索引は維持する。フォルダの改名・移動では子項目のピン留めも新パスへ移し、ゴミ箱移動では対象配下のピン留めを除去する。

新規書類の本文は`WorkspaceDocumentTemplate`で決め、保存先はワークスペースの選択フォルダから決める。空白を既定にし、従来のDocumentGroup新規書類は既存のスターター本文を維持する。書類は排他作成し、本文の書き込みに失敗した場合は作成したファイルを除去する。

文字コードを指定した取り込みは、元ファイルを読み込んで候補ごとの先頭プレビューを示し、選択した形式へ別ファイルとして変換保存する。デコードとエンコードの往復検査で損失や置換文字が生じる候補を拒否する。通常のDocumentGroupはUTF-8書類を編集するため、UTF-8への変換保存後のみその書類を開く。元ファイルを暗黙には書き換えない。

UTF-8書類の改行形式とBOMは本文から分けて`MarkdownDocument.format`に保持する。編集モデルへ渡す本文はLFに統一し、保存時に読み込み元のLF・CRLF・CRとBOMを再生成する。文字コードメニューで明示的に改行形式とBOMを切り替えると、本文文字列を変更せず保存形式だけ変わる。混在改行は改行の数が変わらない間は各行の元の形式を保持し、行数変更後は最多の形式（同数ならCRLF、次にCR）を使う。

書類ごとの作業位置は既存の`DocumentDisplayState`に選択範囲、編集スクロール位置、分割比、サイドバーの表示とアウトライン／ファイル選択を追加して保存する。本文ファイルには書き込まない。初めて保存した書類の表示モードだけが登録されている場合は位置を復元せず、現在の選択を維持する。復元する選択範囲は現在の本文長で切り詰める。分割位置はドラッグとアクセシビリティの増減操作で調整する。

フォルダ検索はセキュリティスコープを保持するワークスペースの索引をバックグラウンドで走査する。対象・除外のカンマ区切りglobを相対パスへ適用し、UTF-8本文を改行正規化して検索する。結果はUTF-16範囲と行番号を持ち、別書類を開いた後に既存の編集モデルへ選択範囲を渡す。検索は取り消し可能で上限2,000件とし、索引が切り詰められた場合は結果が不完全になるためエラーを示す。

複数ファイル置換は検索結果と各ファイルの元データから計画を作り、ファイルごとの局所的な変更前後をプレビューする。上限10,000一致で、対象ファイルを選べる。適用前に開いている書類と元データのSHA-256を確認し、選択した全ファイルを検査してから書き込む。書き込みが途中で失敗したときは触れたファイルを元データへ戻す。元の改行形式とUTF-8 BOMは`MarkdownDocument`の形式情報で保持する。

構造別検索は通常の文字列一致を`MarkdownAnalysis`のブロック範囲で絞る。コード、見出し、本文の順に優先判定するため、引用内のコードも本文へ紛れない。本文には段落、リスト、引用、表を含む。全体検索と一括置換で同じ構造フィルターを使い、複数ブロックをまたぐ一致は構造別検索から除外する。
