# 設計判断

## 方針

CodiMD の特徴のうち、Markdown ソースとレンダリング結果を同時に確認できる編集体験を採用した。サーバー、アカウント、リアルタイム共同編集は本アプリのローカル書類モデルとは責務が異なるため、初期版には含めない。

## macOS 標準コンポーネント

- `DocumentGroup` と `FileDocument` で「新規」「開く」「保存」「別名で保存」と自動保存をシステムに委ねる。
- `NSTextView` と `NSScrollView` で、Undo、検索バー、スペルチェック、キーボード操作、アクセシビリティを提供する。
- `HSplitView` で編集領域とプレビュー領域の幅をユーザーが調整できるようにする。
- `ToolbarItem` とセグメント形式の `Picker` で表示モードを切り替える。
- SF Symbols とセマンティックカラーを使用し、ライト／ダークモードに追従する。

## Markdown 処理

プレビューは文書全体の `MarkdownAnalysis` からブロックを取得し、Foundation の `AttributedString` Markdown パーサーでインライン要素を処理して `NSAttributedString` に変換する。各ブロックは原文のUTF-16範囲、親ブロック、コード言語を保持する。見出し、引用、リスト、コードブロックには AppKit の標準フォント、色、段落スタイルを付ける。Web コンテンツや独自 HTML を埋め込まないため、表示がシステムの文字設定とアクセシビリティに自然に追従する。

現在の `MarkdownAnalysis` は既存表示の構文を対象とする位置付き基盤であり、CommonMarkやGFMの完全な解析器ではない。複数行段落、複数段落のリスト、参照リンク、表などの解釈は個別の構文項目で追加する。表示は当面ソース順にブロックを描画し、親子関係に応じたインデントや装飾もそれぞれの項目で追加する。

書式入力は純粋関数 `MarkdownFormatter` として分離し、UTF-16 ベースの `NSRange` を扱う。これにより `NSTextView` の選択範囲と日本語入力を安全に接続し、UI を起動せず単体テストできる。

書式コマンドは置換対象の `NSRange`、置換文字列、変更後の選択を計画する。`NSTextView` には対象範囲だけを通知して `NSTextStorage` を更新する。全文を `string` に代入すると Undo 履歴が失われるため、書式操作では行わない。IME の未確定文字列がある間と編集が拒否された場合は変更しない。Undo の結合は AppKit のイベント境界に従い、別イベントで実行したコマンドが個別に戻ることをテストする。

解析器が返す位置は1始まりの行・UTF-8バイト列、AppKitの選択位置はUTF-16単位として `MarkdownPositionMap` で相互変換する。Unicodeスカラーの途中を指す位置は拒否する。CRLFは1つの改行として扱い、次行の開始位置はLFの直後とする。結合文字のスカラー境界は保持する。

編集セッションの選択範囲・スクロール位置・フォーカス復帰の意図は、書類画面ごとの `MarkdownEditorModel` が保持する。表示切替で `NSTextView` が破棄される際は参照を解除し、新しいビューの接続時に状態を復元する。外部更新などで本文が短くなった場合は選択範囲を本文内へ収める。フォーカスはビューがウインドウへ接続された後に復元する。

見出しレベルはメニューからH1〜H6と本文を選べる。既存のATX見出し記号と末尾の閉じ記号を取り除いて対象行だけを書き換える。本文行を本文に変換するなど、変更内容が同じ場合は編集通知やUndo項目を作らない。

`DocumentGroup` の構成から渡される `fileURL` を書類画面の `DocumentContext` に反映する。未保存書類では相対リソースを解決せず、保存・移動・別名保存でURLが更新されるたびに基準ディレクトリも変わる。書類本文の読み書きは引き続き `FileDocument` に任せ、URLから本文を再読込しない。参照: [Apple DocumentGroup](https://developer.apple.com/documentation/SwiftUI/DocumentGroup)。

設定は `EditorSettingsStore` で本文と分離して保存する。表示モードは書類ごとの値、最も近い親フォルダの指定、アプリ共通の既定値の順に解決する。フォントサイズもフォルダ指定からアプリ共通値へフォールバックする。以前の `SceneStorage` の表示モードは、書類ごとの設定が未登録のときに限り一度取り込む。未保存書類の表示モードはその画面内に保持し、保存時に書類の設定へ移す。

書式・検索の操作名、ショートカット、実行処理は `EditorCommand` に集約する。メニュー、ツールバー、右クリックメニューはこの定義を使い、編集ビューがない場合や編集不可・IME変換中は無効化する。実行時にはその画面の `MarkdownEditorModel` を渡し、別ウインドウの書類を変更しない。

連続した通常行は1つの段落ブロックとし、行間の改行を `MarkdownLineBreak` の通常・明示に分けて保持する。末尾の2個以上の空白またはエスケープされていないバックスラッシュは明示改行として描画し、通常改行は空白として描画する。原文範囲には改行記号と書式記号をそのまま残す。

リスト項目は元のインデントと親項目を解析結果に保持する。同じ項目内の直後の行は1つ目の段落へ続け、空行の後で字下げされた段落はその項目の子ブロックにする。番号付きと箇条書きの混在を許し、プレビューでは深さに応じた段落インデントを付ける。

連続する引用行は1つの引用ブロックにまとめ、引用記号を1段取り除いた行を既存のブロック解析に再帰的に渡す。これにより引用内の複数段落、リスト、フェンスコード、入れ子の引用を同じ構文木から描画する。子ブロックの原文範囲は引用記号を含む元の行のUTF-16範囲を保持する。段落の直後に限り、引用記号のない次行を遅延継続として取り込む。空行、リスト、フェンスコードの後では引用を終える。

コードブロックはバッククォートとチルダのフェンスを区別し、開始フェンスの文字・長さ・言語名を解析結果に残す。閉じフェンスは同じ文字で開始フェンス以上の長さを要求し、最大3スペースの字下げを許す。4スペース以上の字下げはインデントコードとして扱い、内部の空行と追加の字下げを本文に残す。リスト項目内では項目本文の開始位置からさらに4列以上の字下げを子コードブロックとする。通常段落の途中でインデントコードを開始しない。構文規則の参照: [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/#indented-code-blocks)、[フェンスコード](https://spec.commonmark.org/0.31.2/#fenced-code-blocks)。

Setext見出しは、直前に連続する段落行がある場合だけ`=`または`-`の下線を見出し記号として消費する。これにより`本文\n---`はH2、単独の`---`は区切り線になる。ATX見出しは最大3スペースの字下げ、空見出し、前に空白がある末尾の閉じ記号に対応する。区切り線は同じ記号3個以上で、記号間の空白・タブを許す。原文の範囲には見出し記号や下線を含める。構文規則の参照: [CommonMarkの見出しと区切り線](https://spec.commonmark.org/0.31.2/#thematic-breaks)。

GFM表はヘッダーと区切り行の列数が一致する場合だけ表ブロックにする。区切り行のコロンから列揃えを決め、本文行の不足列は空セルで補い、余分な列は無視する。エスケープされていない`|`を列区切りとし、引用・リスト内でも親ブロックと原文のUTF-16範囲を保持する。表を含むプレビューは縦スクロール領域内に各表専用の横スクロール領域を置く。セル内のインラインMarkdownは既存のパーサーで表示し、見出しとセルの内容には読み上げラベルを付ける。仕様の参照: [GFM Tables](https://github.github.com/gfm/#tables-extension-)。

GFMの`[ ]`・`[x]`・`[X]`はリスト項目の最初の段落の先頭だけでタスク状態として認識する。原文と選択用のUTF-16範囲を変えず、表示時に記号を「☐ 未完了」「☑ 完了」へ置き換える。プレビューはテキストとしてキーボード選択でき、状態名を文字で含むため読み上げ時も区別できる。チェック操作による本文変更は表示機能とは別の編集コマンドとして扱う。仕様の参照: [GFM Task list items](https://github.github.com/gfm/#task-list-items-extension-)。

取り消し線の調査では、FoundationのMarkdownパーサーが`~~文字~~`をインライン意図として解析する一方、`NSAttributedString`への変換結果では意図属性の値が`NSNumber`になり、従来の`InlinePresentationIntent`への直接キャストで取り出せないことが分かった。数値から意図を復元し、取り消し線には`strikethroughStyle`を適用する。同じ経路を通る太字・斜体・インラインコードも回帰テストで確認する。取り消し線の構文は[GFM Strikethrough](https://github.github.com/gfm/#strikethrough-extension-)に従う。

参照形式のリンク・画像は、ブロック解析中に文書全体の定義を先に集め、最初の定義を採用する。ラベルは前後や連続する空白を正規化して小文字化し、通常の`[文字][ラベル]`、`[ラベル][]`、`[ラベル]`を解決する。定義行はプレビューから除き、原文のUTF-16範囲を参照情報に保存する。引用・リスト・表セルでも共通の定義を使う。インラインコード内やエスケープした構文は置換しない。画像参照は画像表示機能の追加前は「画像: 代替テキスト」という参照先へのリンクで示す。仕様の参照: [CommonMark Link reference definitions](https://spec.commonmark.org/0.31.2/#link-reference-definitions)。

太字・斜体・インラインコードのコマンドは同じ範囲で再実行すると記号を外す。カーソルが書式の内側にある場合もその書式を解除し、カーソルが記号の外側にある場合は新しい書式を挿入する。選択が既存の書式と一部重なる場合は記号を含む範囲まで広げ、未書式の文字を含む選択は単一の書式にまとめる。全体が書式付きなら記号を外す。太字の`**`・`__`、斜体の`_`・`*`、長さの異なるバッククォートを対象とし、エスケープした記号やコードスパン内の記号を既存の書式と誤認しない。コードスパンの検出は参照リンク処理とも共有する。変更範囲とカーソル位置はUTF-16で管理し、Undoは従来の編集モデルに委ねる。

取り消し線の挿入は書式トグルの共通処理を使う。選択範囲を`~~`で囲み、空選択には選択済みの「取り消し線」を入れる。再実行では同じ規則で解除する。メニューと右クリックメニューから使え、ショートカットはCommand＋Shift＋Xとする。既存のGFMプレビューが挿入結果を表示する。

番号付きリストの挿入は選択された各行をUTF-16の行範囲で処理する。箇条書き・既存の番号記号を外し、最初の項目が番号付きなら開始番号を維持して連番を振る。字下げと改行形式は保持し、空行は項目化しない。空文書や空行にカーソルがある場合は`1. `を入れて記号の後ろにカーソルを置く。コマンドはMarkdownメニューと右クリックメニューから実行できる。

タスクリストの挿入は番号付き・箇条書きと同じ行解析を使う。選択した各項目を`- [ ] `に変換し、既存の`[x]`・`[X]`は完了状態を維持する。箇条書きコマンドでタスクのチェック記号を外せる。空行は維持し、空文書や空行のカーソルでは記号の後ろへ挿入位置を移す。番号付きリストへ変換する際は既存タスク状態を本文に残す。リストの記号変換は原文の行末形式と字下げを保つ。

タスクの完了切替は解析済みタスク項目の原文行だけを対象とし、コードブロック内にある同じ文字列は変更しない。カーソル行ではその項目を切り替え、複数選択では全項目が完了なら未完了へ、それ以外なら完了へ揃える。状態の1文字だけを置換するため本文の長さ・選択位置・行末形式は変わらない。編集画面とプレビューのチェックボックスは同じ`MarkdownFormatter.toggleTasks`を使い、編集画面では`NSTextView`のUndo、プレビュー専用表示では文書の`UndoManager`に変更を登録する。チェックボックスには項目名を含む読み上げラベルを付ける。

コードブロック挿入は、選択範囲にある連続バッククォートの最大長より1文字以上長く、最短3文字のフェンスを使う。選択した内容はそのままフェンス内に残し、空選択では空のコード行にカーソルを置く。選択が行の途中にある場合は前後に改行を追加してフェンスを独立した行にする。既存文書がCRLFなら挿入する改行もCRLFに合わせる。言語はメニューと右クリックメニューで「言語なし」、Swift、JavaScript、TypeScript、Python、JSON、Bash、Markdownから選ぶ。言語名は固定した識別子を出力し、任意の未検証文字列をフェンスの情報文字列に入れない。

区切り線の挿入には`***`を使い、文書冒頭でもYAMLフロントマターと重ならないようにする。選択範囲がある場合はその文字列を置き換え、前後に既存の空行を数えて必要な改行だけを追加する。行の途中なら本文を分け、区切り線の前後を空行で区切る。これにより直前の段落をSetext見出しとして解釈させない。改行形式は既存文書に合わせ、挿入後のカーソルは区切り線の後ろへ置く。

リンクコマンドは書類ごとの編集モデルからシートを開き、表示名・URL・任意のタイトルを編集する。カーソルが既存のインラインリンク内にある場合は表示名・URL・タイトルを読み込み、保存時にリンク全体を置き換える。URL中の空白・制御文字・山括弧は百分率符号化し、丸括弧とバックスラッシュはMarkdownのバックスラッシュでエスケープする。タイトルの引用符とバックスラッシュ、表示名の角括弧も共通の構文処理でエスケープする。既存の装飾付き表示名を変更しない場合は原文の記号を残す。シートを開いてから本文が変わった場合は古い位置への書き込みを拒否する。編集は従来の`NSTextView`経路を通してUndo可能にする。構文規則の参照: [CommonMark Links](https://spec.commonmark.org/0.31.2/#links)。

画像挿入シートはURLとファイルを選択でき、代替テキストを必須、タイトルを任意とする。画像構文はリンクと同じURL・タイトルのエスケープ処理を使う。文書内にある画像ファイルは相対パスで参照し、文書外のファイルは文書横の`assets`へコピーする。保存名が重なる場合は連番を付け、画像形式は拡張子とImageIOの内容判定で確認する。`assets`が文書外へのシンボリックリンクならコピーを拒否する。ファイルコピーは別タスクで行い、本文変更などで挿入できなかった場合は今回作成したファイルを削除する。未保存文書ではファイル選択を使えず、保存後に挿入する。相対パスの解決は`DocumentContext`を使い、後続のローカル画像表示・ドラッグ＆ドロップ・貼り付けも同じ`ImageResourceManager`を使えるようにする。

編集画面のMarkdown構文色分けは`NSTextStorage`を書き換えず、`NSLayoutManager`の一時的な文字色属性を使う。ブロックの見出し・コード・区切り線・表は`MarkdownAnalysis`の原文範囲から求め、引用・リスト・タスクの記号とインラインコード・リンク・強調記号をUTF-16範囲で補う。コードブロックとコードスパン内の他の構文は装飾しない。入力と外部更新の後に再適用し、IME未確定文字列がある間は更新しない。表示のみの処理なのでUndo履歴と原文は変えない。大きい文書向けの差分解析・再描画はB07で検討する。

インラインライブ表示は初期状態で無効の追加モードとする。非アクティブ行のMarkdown記号だけを第三ラベル色にし、選択・編集中の行は既存の構文色へ戻す。テキストを隠したり置換したりせず、TextKitの一時的な文字色だけを変更するため、選択位置、コピー内容、Undoとアクセシビリティの原文は同じになる。IME未確定文字列がある間は更新しない。共有解析が古い間は同期再解析を行わず、最新の解析結果が届いてから更新する。コードブロック内の見かけ上の記号は対象外にする。

タイプライターモードは初期状態で無効にし、本文が編集された時だけキャレット行の中央位置からスクロール先を計算する。カーソル移動や表示切替では追従しない。ホイールとライブスクロール中、および終了後1.5秒は利用者の手動位置を優先する。IME未確定中も動かさず、可視領域の1割以内の小移動は省いて揺れを抑える。先頭・末尾では書類のスクロール可能範囲に収める。原文・選択・Undoには触れない。

用語辞書はアプリ共通設定に禁止表記と推奨表記の組をローカル保存し、上の項目を優先する。既定ではコードと引用を除外し、どちらも設定で変更できる。リンク先URLは置換候補から常に除く。照合は原文のUTF-16範囲を保持し、入力停止後180msにスナップショットをバックグラウンドで確認する。前の確認は取り消し、本文と辞書が一致する結果だけを表示する。結果の置換は本文が診断時と同じ場合だけ範囲編集として適用し、Undoに登録する。空欄と同一表記の項目は照合しない。

タグ索引は本文の`#名前`と、先頭フロントマターの`tags`スカラー・角括弧リスト・インデント付きリストを対象にする。名前は英字またはUnicode文字かアンダースコアで始め、続きに数字・ハイフン・スラッシュを許す。比較は小文字化し、見出し記号、コードブロック、インラインコード、URL、リンク先、フロントマターの本文を誤認しない。YAMLの複雑な引用・入れ子・エイリアスは対象外で、M12/K02の専用編集で拡張する。ワークスペースの既存ファイル索引を使い、開いている書類は未保存本文を優先する。1書類8MBを上限とし、読めない書類・索引打ち切りは件数や注意を表示する。索引作成はバックグラウンドで行い、シートを閉じたら取り消す。

文書プロパティは既存インスペクタから編集する。UIに出すのは先頭フロントマターの単一行スカラーだけとし、複雑なYAML値は原文で編集する。既存値の変更は値のUTF-16範囲だけを置換し、行末コメント・未知のキー・ネストした行を保持する。新規キーは閉じ区切りの直前へ、フロントマターがない場合は文頭に区切りとともに挿入する。キーは英字で始まるASCIIの英数字・ハイフン・アンダースコアへ制限し、改行を含む値と引用符なしでコメントと解釈される`#`は拒否する。削除は対象の単一行だけを除く。すべて既存のUndo経路を使い、CRLFは維持する。同名の複雑な値がある場合は重複キーを作らず編集を拒否する。

バックリンクは現在の保存済み書類を対象にワークスペース内のMarkdown書類を走査し、共有済みのリンク解析からインライン形式と参照形式の参照元を集める。コード内・画像・外部URL・フロントマター内は対象外にする。開いている書類は未保存本文を優先し、結果にはファイル相対パス、行番号、短い抜粋と原文範囲を保持する。選択時は対象書類を開き、その範囲へ移動する。1書類8MBを上限とし、読めない書類と索引打ち切りを表示する。走査はバックグラウンドで行い、画面を閉じたら取り消す。

Wikiリンクは `[[文書名]]` と `[[文書名|表示名]]` に対応する。文書を含むフォルダからの相対パスが実在すれば優先し、文書名だけの指定はワークスペース内で一意の場合に限り解決する。同名文書が複数あり相対パスでも決まらない場合は未解決のままにし、補完画面では相対パスを挿入する。コード・フロントマター・エスケープされた記号は解析しない。補完、リンク先を開く、標準Markdownへの変換はインスペクタのシートから行い、編集は既存のUndo経路を使う。ワークスペース内の移動・改名では解決済みWikiリンクだけを新しい位置に合わせて更新し、プレビューとロールバックを既存のファイル操作に含める。バックリンク索引も同じ解決規則を使う。

他文書の埋め込みは単独行の `![[文書名]]` または `![[文書名#見出しスラッグ]]` とする。Wikiリンクと同じ解決規則を使い、指定見出しから次の同階層以上の見出しまでを抽出する。展開時にコードブロックとフロントマターは走査せず、祖先文書への循環参照を止め、深度を4段階、各依存文書を1MBに制限する。プレビューは3秒ごとに保存済み・未保存の依存文書を読み直し、対象がない場合や制限に達した場合は本文を変更せず状態を表示する。入れ子の埋め込みで使う相対インラインリンク・画像は表示先の文書位置に合わせる。構文はMarkdown標準ではないため、原文と他の処理系では記号のまま残る。

日付ノートは利用者のカレンダー上の日付をグレゴリオ暦の `YYYY-MM-DD` に変換し、ワークスペースの `Daily` フォルダへ保存する。選択したテンプレートは新規作成時だけ適用し、同じ日付のファイルがあれば内容を変更せず開く。フォルダや書類の作成には既存のワークスペース内パス検証を使い、シンボリックリンク経由で外部に作成しない。

日付ノートの検証で、存在しない最終ファイルまで含む `resolvingSymlinksInPath()` は親フォルダのシンボリックリンクを十分に検証できない場合があると分かった。作成先・移動先は存在する親フォルダを先に実体パスへ解決してから末尾の名前を付ける。日付ノートだけでなく汎用の作成・移動処理にも同じ修正を適用し、ワークスペース外を指すシンボリックリンクの回帰テストを追加した。

ワークスペースのタスク一覧は既存のMarkdown解析で未完了と判定されたチェック項目のみを集める。コードブロックは含めず、開いている書類の未保存本文を優先する。一覧から完了にする時は対象書類を開き、索引作成時の行が同じ位置に同じ内容で残っていることを確認する。変更は既存の書式編集とプレビュー編集のUndo経路を使い、一覧作成後に変わった行には適用しない。期限記法は導入しない。読み込めない書類と索引上限は一覧に表示する。

文書間リンクのグラフは通常のMarkdownリンク、Wikiリンク、他文書の埋め込みから重複のない有向辺を作る。コード内・画像・外部URL・フロントマター内のリンクは対象外で、未保存本文を優先する。初期表示は現在文書と直接つながる文書に絞り、全体表示は利用者が選んだときだけ計算済み索引から最大150書類を描く。グラフ上の点と隣の書類一覧から対象を開ける。索引上限と読めない書類を表示し、走査はバックグラウンドで取り消せる。

文書の分割では現在の見出しから次の同階層以上の見出しまでを新規書類に抽出し、抽出先の最上位見出しをレベル1に調整する。元書類の同じ位置には見出しと新書類へのリンクを残し、既存の `元書類#見出し` 参照が切れないようにする。新書類を排他的に作成してから元書類をUndo可能な編集で変更し、編集を拒否された場合は作成した書類の内容を照合して削除する。結合は最大10書類の未保存本文または保存済み本文を読み、新規書類へ順にコピーする。元書類は変更せず、各書類名をレベル1の見出しにして元の見出しを一段下げる。フロントマターはYAMLコードブロックとして残す。両操作ともインライン・参照形式のローカルリンク、画像、Wikiリンク、埋め込みの相対位置を新しい保存先に合わせる。コード内のリンクは変更しない。

分割後のUndoは元書類の編集だけを戻す。作成先は独立した書類として残し、その後の編集をUndoで誤って削除しない。作成直後に元書類の編集が失敗した場合だけ、作成先の内容が一致することを確認して復元する。

名前付き作業レイアウトはワークスペースごとの利用者設定に保存し、本文へ混ぜない。開いている書類の相対パスと現在の書類を記録し、表示モード、サイドバーのタブと可視状態、分割比率・方向・先頭側を保存する。復元時は書類の選択範囲とスクロール位置を保持し、現在開いているウインドウにも共有イベントで配置を適用する。保存済み書類を順に開き、元の現在書類を最後に開く。削除済み・ワークスペース外の書類は開かずに通知し、レイアウトから自動削除しない。ファイルやフォルダの移動時は保存した相対パスを更新する。同名で保存した場合はそのレイアウトを更新する。

行番号は`NSScrollView`の縦`NSRulerView`に表示し、本文の保存内容には含めない。`NSLayoutManager`の行フラグメントから画面上の位置を得て、各フラグメントの先頭が原文の論理行頭である場合だけ番号を描く。これにより折り返し行で番号が重複しない。空文書と末尾改行後の空行も1行として表示し、CRLFを1つの行区切りとして数える。入力・外部更新・スクロールでガターを再描画し、桁数に応じて幅を変える。TextKitの行フラグメント列挙と`NSRulerView`の描画・幅変更はAppleの[NSLayoutManager](https://developer.apple.com/documentation/appkit/nslayoutmanager/enumeratelinefragments(forGlyphRange:using:))と[NSRulerView](https://developer.apple.com/documentation/appkit/nsrulerview)を使用する。

Returnキーでのリスト・引用継続は`NSTextView.insertNewline`から編集モデルへ渡し、通常の範囲編集とUndo経路を使う。箇条書きは同じ記号、番号付きリストは番号を1増やして区切り記号を保持し、タスクは未完了`[ ]`で継続する。引用は元の階層を引き継ぐ。空のリスト項目ではリスト記号を外し、引用内なら引用階層を残す。空の引用行では最も内側の引用記号を1つ外す。コードブロック内、選択範囲あり、IME未確定中は補助せず標準の入力処理に委ねる。編集が拒否された場合も別の改行を挿入しない。原文の改行形式はCRLF・CR・LFを維持する。

リストのTab／Shift-TabとMarkdownメニュー・右クリックメニューは同じ`MarkdownIndentation`を使う。選択されたリスト項目の行と解析器が示す子ブロックの行をまとめて2スペース移動し、引用内では`>`の後にスペースを出し入れする。空行と選択外の兄弟項目は変えず、最上位の項目をアウトデントした際に子だけを動かさない。コードブロックでは通常の字下げとして4スペースを扱い、カーソルだけのTabはその位置に挿入する。変更は1つのUTF-16範囲編集にまとめ、Undoと選択位置の変換を既存のモデルに委ねる。通常の段落はAppKitのTab処理に任せる。

記号の自動補完は`NSTextView.insertText`で1文字の入力を受けたときに実行し、`()`・`[]`・`{}`・バッククォート・`*`・`_`を対にする。選択文字列は対の内側へ残し、選択も内側へ移す。選択中にバッククォートが含まれる場合は、内部の連続数より長い記号を使う。奇数個のバックスラッシュ直後は補完せず、コードブロックとコードスパン内ではMarkdownの強調記号・バッククォートを補完しない。括弧はコード内でも補完する。IMEの置換範囲指定中と未確定文字列がある間はAppKitの入力へ委ねる。補完も既存の範囲編集を通してUndo可能にし、編集拒否時は別の文字を挿入しない。

表挿入はメニュー・右クリックからシートを開き、データ行数1〜20、列数1〜12を指定する。`列1`から始まる見出し、GFM区切り行、空のデータ行を原文へ挿入し、先頭の見出しセルを選択する。表の前後に必要な空行を追加して隣接段落と分け、CRLF・CR・LFを維持する。シートを開いた後に本文が変わった場合は古い選択位置への挿入を拒否する。列揃えと既存表の行列編集はT02・T03で扱う。

ローカル画像のプレビューはMarkdownパーサーの[画像URL属性](https://developer.apple.com/documentation/foundation/nsattributedstring/key/imageurl)を読み、`DocumentContext`から相対パスを文書の場所に解決する。参照形式の画像も通常の画像構文へ解決して同じ経路を通す。ImageIOで最大960ピクセルのサムネイルを作り、表示は最大480×320ポイントとしたうえで、[TextKitの添付レイアウト](https://developer.apple.com/documentation/appkit/nstextattachmentcontainer)が実際の行幅へさらに縮小する。画像と添付文字に代替説明を付ける。未保存文書・画像が見つからない場合・URL画像は「画像: 代替テキスト」のリンクで表示し、URL画像の自動ダウンロードは行わない。画像の読み込みは現状同期であり、大きな文書の処理はB07の非同期表示と合わせて見直す。

画像ファイルのドラッグ＆ドロップは`EditorTextView`が画像形式のファイルURLを1つだけ受け、TextKitでマウス位置をUTF-16の挿入位置に変換する。ドラッグ中はアクセント色の挿入線を描き、取消時は元の選択範囲へ戻す。Markdownメニューの「画像ドロップ」で、外部ファイルを`assets`へコピーするか元ファイルへの相対パスにするかを選ぶ。文書内のファイルはどちらの設定でもそのまま相対参照する。設定はアプリ共通を保存し、フォルダ設定があればそれを優先する。コピー時は既存の`ImageResourceManager`を使用し、本文や書類URLが非同期処理中に変われば挿入を拒否して作成ファイルを削除する。編集とUndoは既存の範囲編集経路を使い、ドロップにより挿入する代替テキストはファイル名から拡張子を除いたものとする。

標準の貼り付け操作は、ペーストボードにPNGまたはTIFF画像データがある場合だけ画像処理へ進み、通常のテキストではAppKitの貼り付けを使う。画像はImageIOで検証・PNG化して`assets/screenshot-年月日-時分秒.png`へ保存し、同秒の衝突には連番を付ける。選択文字列を画像構文で置き換え、代替テキストは「スクリーンショット」とする。本文や書類URLが変わった場合は挿入せず、今回作成したPNGを削除する。未保存文書では保存先が必要なため標準の保存操作へ案内し、保存後に再度貼り付ける。保存前に画像データを一時保管して後日の保存時に意図せず挿入することは避ける。

管理フォルダは文書横の`assets`に固定し、文書外を指すシンボリックリンクなら保存しない。ファイル取り込みではいったん`assets`内の隠し一時ファイルへコピーし、内容が既存の通常画像ファイルと同一ならその相対パスを再利用する。違う内容で同名なら`-2`以降を付ける。スクリーンショットの貼り付けは各操作を別添付として連番保存する。一時ファイルから最終名への移動後にだけ本文へ画像構文を挿入するため、コピー・PNG化・移動の失敗では本文を変えず一時ファイルを消す。挿入が拒否された場合はその操作で新規作成したファイルのみ削除し、既存の再利用ファイルは残す。`FileDocument`の後続の自動保存が失敗した場合は画像ファイルを保持し、未保存の本文から再保存できるようにする。不要になった添付の自動削除は、他文書からの参照を識別できるワークスペース索引を導入するまで行わない。

編集文字のフォント・サイズ・行間・余白はアプリ共通設定で管理する。フォントサイズには既存のフォルダ別設定を優先し、文字表示メニューの拡大・縮小はアプリ共通サイズだけを変える。フォント種類はサイズ操作とは独立させ、設定画面で選択する。`NSTextView`の既定段落スタイルとインセットに表示設定を適用し、本文文字列やUndo履歴は変更しない。以前の保存データに新しい項目がない場合はシステム等幅フォント、左右・上下18ポイントを使う。

折り返し設定は`NSTextView`の横方向のサイズ変更、テキストコンテナの幅追従、水平スクローラを一緒に切り替える。折り返さないときはレイアウト済み文字の幅から文書ビューの幅を更新し、長い行の末尾までスクロールできるようにする。表示幅は入力・外部更新・ウインドウ幅変更でも更新する。タブ表示幅は選択したフォントの空白幅を基準に段落スタイルへ設定する。リストとコードの字下げ幅は別設定とし、編集コマンドの範囲編集へ渡す。以前の保存データでは折り返し有効、タブ4文字、リスト2文字、コード4文字を既定とする。長い行の幅が変わらない不具合を再現テストに固定した。

見出し・表・タスクを含むプレビューは構造ごとのSwiftUI要素を使う。見出しにはヘッダー特性とレベルを含む読み上げ名、表セルには列見出しと行番号、タスクには内容を含むチェックボックス名を付ける。リンクはレンダラーが付けるURL属性を保持する。装飾用の引用線はアクセシビリティツリーから除く。構造付きプレビューはキーボードのフォーカス対象とし、タスクのチェックボックスへも移動できる。編集ビューの再作成時には既存の編集セッションのフォーカス復帰処理を使う。通常の段落だけの文書は従来の選択可能な`NSTextView`プレビューを維持する。見出し等がある場合の選択操作とVoiceOverの読み上げ順序は実機でも確認する必要がある。参照: [Apple SwiftUIのヘッダー特性](https://developer.apple.com/documentation/swiftui/accessibilitytraits/isheader)、[アクセシブルな移動](https://developer.apple.com/documentation/swiftui/accessible-navigation)。

文書画面ごとに`DocumentAnalysisStore`を持ち、変更された本文の不変スナップショットから構文木・統計・構文色分け範囲を一度に作る。解析はメインスレッド外のタスクで実行し、結果だけをMainActorで公開する。更新ごとに世代番号を進め、遅れて完了した古い結果を捨てる。同一本文の重複要求はまとめる。本文が公開済みの内容へ戻った場合も処理中の別版を無効にする。解析中は直前のプレビューを表示し、古い原文位置を使うタスク操作は無効にする。初回は解析完了まで進行表示にする。AppKitの一時表示属性とプレビュー描画はMainActorで行い、IME未確定範囲の装飾は従来どおり避ける。書式コマンドの候補判定など利用者が明示した操作時の解析は独立したままにし、入力ごとの再解析を集約する。

アウトラインは解析済みの見出しブロックを原文順に並べ、見出しレベルで字下げする。サイドバーはmacOS標準の`NavigationSplitView`を使い、ツールバーから表示を切り替える。選択時は見出しのUTF-16開始位置へ編集カーソルを移し、プレビューの対応ブロックIDをスクロール先にする。プレビュー専用表示では次に編集ビューが接続されたときに選択とスクロールを復元する。古い解析結果の位置へ移動しないように、編集中で解析結果が古い間はアウトラインの選択を無効にする。表示対象の見出しが消えたときは新しい解析結果の見出し一覧へ更新する。

現在のセクションはカーソル位置以前に現れる最後の見出しとする。最初の見出しより前には現在セクションを付けず、同名見出しは表示名ではなくブロックIDで区別する。解析結果が編集中の本文に追いついているときだけサイドバーの該当行を強調し、読み上げにも選択状態を渡す。

指定行への移動はUTF-16の行頭索引を作って行番号を位置に変換する。CRLFを1つの改行として数え、CRとLF単独、末尾改行後の空行も扱う。1未満または最終行を超える番号は有効な範囲へ補正し、シートにもその規則を示す。プレビュー専用表示からは編集表示へ切り替えた後にカーソルを目的行へ移し、再生成される編集ビューが接続された時点でスクロールする。通常の文字入力とUndo履歴は変えない。

見出しのクイック検索は共有アウトラインの項目を対象とし、利用者の入力を前後空白を除いてローカライズされた部分一致で絞り込む。同名見出しも別位置として残す。検索欄からReturnで先頭候補へ、Tabで一覧へ移って矢印キーで候補を選んでから移動ボタンで確定できる。解析が古い間は古い位置へ移動しないよう候補を表示しない。移動処理はサイドバーと同じ経路を使う。

ナビゲーション履歴は書類URLとUTF-16位置の組を保存する。アウトライン・見出し検索・指定行・プレビューから原文への明示的な移動で出発点を積み、通常の文字入力やカーソル移動では履歴を増やさない。戻る操作時の現在位置を進む側へ積み、新しい移動で進む履歴を消す。履歴は画面ごとに最大100件とし、Undo履歴とは分ける。未保存書類の初回保存や別名保存では履歴内の書類URLを新しいURLへ移す。現在のUIで利用できる戻る・進むは同じ書類内の移動を対象とする。書類間の履歴復帰にはアプリ共通の履歴管理が必要となる。

文書内見出しリンクのIDはGitHubの見出しアンカー規則に合わせる。表示文字列からMarkdown装飾を除いて小文字化し、空白をハイフンへ変え、元からあるハイフンとアンダースコアを残し、その他の空白・句読点・記号を除く。同じIDが先にあれば`-1`から連番を付け、既存の文字列と衝突するときはさらに番号を進める。空になる見出しは`section`を基底IDとする。`#fragment`だけのURLを文書内リンクとして扱い、プレビューのSwiftUIリンクとAppKitテキストリンクの両方を同じ索引へ渡す。見つからなければ案内し、見つかればアウトラインの移動経路を使って履歴・編集カーソル・プレビューの位置を揃える。相対ファイルパス付きリンクはL02で扱う。参照: [GitHubの見出しアンカー規則](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#section-links)、[github-sluggerの実装](https://github.com/Flet/github-slugger/blob/master/index.js)。

相対Markdownリンクは現在書類のフォルダを基準に解決し、`.md`と`.markdown`だけを標準の`openDocument`アクションへ渡す。外部URLはシステムへ渡し、未保存書類には基準フォルダがないため相対リンクを開かない。リンクにフラグメントがあればアプリ共通の一時的な移動要求として保持し、開いた先の書類で解析が現行本文に追いついた後に見出しへ移動する。開く操作が失敗した場合は要求を破棄してエラーを示す。書類間の履歴復帰は現在の履歴モデルが画面ごとであるため未対応で、後続の複数書類ナビゲーション設計で扱う。

ファイルパス補完は現行書類のフォルダだけを走査し、隠しファイル・パッケージの内部・シンボリックリンクを除外する。最多500件を読み取り、入力文字を含む候補を最大8件表示する。候補選択時は人が読める相対パスを入力欄へ置き、保存時に既存のリンク構文処理で空白や括弧をエスケープする。走査はバックグラウンドで実行し、未保存書類では候補を出さず保存を案内する。macOSの`/var`と`/private/var`の表記差で絶対パスの前方一致が失敗するため、ディレクトリ列挙の階層レベルから相対パスを組み立てる。

リンク編集欄に`#`がある場合、現在書類または入力した相対パスのMarkdown書類だけから見出しIDを生成して候補にする。対象ファイルはUTF-8かつ8MB以下に制限し、読み取りと解析はバックグラウンドで行う。現在書類では共有解析スナップショットを使う。編集中の別ウインドウに未保存変更がある場合、対象書類の候補はディスク上の内容に基づく。参照形式リンクは現在書類の定義済みIDから選び、`[表示名][ID]`として差分編集する。未定義IDは候補に出さない。

選択範囲へ`http`・`https`・`mailto` URLを貼り付けた場合は、選択文字列を表示名にしてリンク構文へ差分編集する。選択なし、URL以外、既存リンクの内部、IME変換中は標準の貼り付けへ戻す。画像データがある場合は既存の画像貼り付けを先に扱う。元のURLを挿入したい場合はコンテキストメニューの「URL をそのまま貼り付け」を選べる。リンク生成は既存のエスケープ処理とUndo経路を共有する。

リンク診断は要求された時点の本文スナップショットに対して実行し、結果の原文範囲を保持する。インラインリンク・画像は既存のリンク構文パーサーで取り出し、明示的な参照形式`[表示名][ID]`は参照定義索引と照合する。コードブロックとコードスパンを除き、相対ファイル／画像の存在、現書類と対象Markdown書類の見出しIDを確認する。対象書類は8MB以下のUTF-8だけ解析し、同じ書類への複数リンクは解析結果を再利用する。裸の`[ID]`は通常の角括弧との区別がつかないため欠落判定しない。診断一覧の項目を選ぶと原文位置へ移動する。

分割表示のスクロール同期は原文位置と解析ブロックIDを使い、スクロール率は用いない。原文側は`NSTextView`の可視上端の文字位置をレイアウトから求め、対応ブロックをプレビューの上端へ送る。プレビュー側は各ブロックの可視位置から上端のブロックを選び、原文の対応行を上端へ送る。プログラムから生じた再通知は最後に同期したブロックIDで抑え、カーソル位置やUndo履歴は変えない。画像の読み込み等でプレビューの高さが変わるとジオメトリを再評価する。分割表示のプレビューはこの対応を保つため構造化ビューを使う。

プレビューから原文への移動はブロック単位のコンテキストメニューとアクセシビリティアクションで提供する。解析ブロックの原文`NSRange`をそのまま選択し、プレビュー単独表示では編集表示へ切り替える。編集ビューが再生成される場合も選択範囲とスクロール要求をモデルに保持する。明示的な移動としてナビゲーション履歴へ記録する。プレビュー単独表示でも原文範囲を取得するため構造化ビューを使う。

表示倍率はアプリ設定に編集用とプレビュー用を別々に保存する。初期値100%、範囲50〜200%、操作単位10%とし、既存設定の読み込みでは値がない場合に100%を使う。編集倍率は設定済みのフォントサイズと行間へ掛け、プレビュー倍率は描画済み属性文字列のフォントへ掛ける。書類本文やリンク属性は変えない。表示倍率メニューは現在値を示し、通常のCommand+プラス／マイナス／0を編集用、Optionを加えた組合せをプレビュー用とする。フォントの基準サイズは設定画面から別途変更できる。

コードブロックは解析で保持したフェンスの言語名から、Swift、JavaScript／TypeScript、Python、JSON、シェルの字句色分けを選ぶ。短縮名も解決する。文字列・コメント・キーワード・数値を順にトークン化し、文字列内のコメント記号やキーワードを誤着色しない。対応外の言語は従来どおり等幅の単色表示とする。色はAppKitのシステム色を使い、段落間隔・原文・コード言語名は変えない。完全な構文解析ではなく、補間文字列、複数行文字列、言語固有の複雑な字句は対象外とする。

構造化プレビューは`LazyVStack`で可視付近のブロックを生成する。解析結果は既存の文書スナップショットを使い、描画属性は表示に必要な内容の組でキャッシュする。原文位置やブロックIDが変わっても同じ内容なら再描画せず、見出し・本文・表セル等が変わった項目だけ作り直す。参照定義の行位置は描画結果に影響しないため、定義のURL・タイトルが変わった時だけキャッシュを破棄する。書類URL・倍率が変わった時も破棄し、保存件数は最大4000で抑える。引用の深さは一度作った親ID索引から求める。構造化プレビューが使われない内部のネイティブ表示では、本文・書類URL・倍率が前回と同じなら`setAttributedString`を繰り返さない。

検索・置換は`NSTextView`で有効にした標準検索バーを使う。検索・次／前・置換画面・すべて置換を`NSTextFinder.Action`のタグで`performTextFinderAction`へ渡し、標準の検索条件とUndoを利用する。メニューには置換とすべて置換を明示し、置換画面はOption+Command+Fで開く。IME変換中は一括置換を実行しない。参照: [Apple NSTextFinder](https://developer.apple.com/documentation/appkit/nstextfinder)、[置換画面アクション](https://developer.apple.com/documentation/appkit/nstextfinder/action/showreplaceinterface)。

大文字小文字・単語単位などの検索条件はAppKitの標準検索バーが提供し、条件メタデータは検索用ペーストボードに保持される。[確認記録](find-bar-verification.md)にSDK/APIの根拠と実機確認の残件を記す。

正規表現検索は標準検索バーと区別したシートで扱う。`NSRegularExpression`をバックグラウンドで実行し、UTF-16の一致範囲を一覧と原文移動へ渡す。置換文字列の`$0`・`$1`等は対象一致のキャプチャへ展開し、存在しない番号をエラーにする。ゼロ幅一致も有限個の一致として処理する。すべて置換は最初から最後の一致を覆う範囲を1回の差分編集にまとめ、Undoで元へ戻せるようにする。選択済みの一致は1件置換でその位置を優先し、次を検索では次の一致へ進む。本文が検索開始時から変わった場合やIME変換中は編集を拒否する。

選択範囲内の一括置換は標準検索バーの`replaceAllInSelection`アクションを使う。正規表現シートは開いた時点の選択範囲を固定し、利用者が「選択範囲内」を有効にすると、そのUTF-16範囲だけを検索する。置換に成功したら編集差分だけ範囲の長さを更新する。範囲外の編集では位置を補正し、範囲境界にまたがる編集や本文外になった範囲は無効として扱う。現在のカーソル選択を検索範囲の代わりに再利用しないので、一致箇所へ移動しても検索範囲が変わらない。

表の行・列操作は`MarkdownAnalysis`の表ブロックと原文行範囲を使い、現在のセルをUTF-16位置で特定する。行の追加・削除は対象行だけを差分編集し、列操作は表ブロックの各行を同じ列数へ組み直す。区切り行には新しい列の`---`を入れ、既存の配置指定とエスケープしたパイプを保持する。ヘッダーと区切り行は削除せず、最後の列も削除しない。各操作は`MarkdownEdit`を1回適用するため、Undoで戻せる。

列の配置変更は選択セルの列番号から区切り行の対象セルを求め、左`---`、中央`:---:`、右`---:`へ差分編集する。メニューのPickerは解析済みの現在値を表示し、表の外では無効化する。ヘッダーと他の列の原文は保持する。

表内のTab／Shift-Tabは原文セルのUTF-16範囲を求めて次／前のセル内容を選択する。区切り行は移動対象から外す。最後のセルでTabを押した場合は、設定が有効なら行追加の差分編集を使い、無効なら表の後へカーソルを移す。IME未確定中と表の外では既存のキー操作を優先する。設定はアプリ共通で保存し、既存の設定データでは行追加を既定で有効にする。

表の整形はGFMと同じく未エスケープのパイプを区切りとし、コードスパン内でも未エスケープなら列境界として扱う。セル内容のエスケープは変えず、列ごとの表示幅に合わせて空白と区切り行を整える。日本語と絵文字は等幅フォントでの幅を2として数える。列配置は区切り行のコロンを維持し、整形前の選択セルを整形後も選択する。表の外の本文は変更しない。

TSV・CSV変換はクリップボードのタブを優先して区切り文字を判定し、引用符内の区切り文字・改行と二重引用符を解析する。先頭行をヘッダーにし、短い行には空セルを補う。Markdownで構文になる記号はエスケープし、セル内改行は`<br>`へ変換する。改行を含む場合は変換前にシートで方針を示し、確定時に元の本文と選択範囲が維持されていることを確認する。CSVの引用符が不正な場合は本文を変更しない。

HTML書き出しはプレビューと同じ`MarkdownAnalysis`のブロック構造を使う。見出しIDは既存の見出し索引に合わせ、表の配置やタスク状態もHTMLに反映する。インライン構文はFoundationのMarkdown解析結果からリンク・強調・画像等を変換する。テキストと属性値はHTMLエスケープし、危険なリンクスキームは出力しない。ローカル画像はデータURLへ埋め込み、CSSもHTMLに同梱して単一ファイルとして保存する。

PDF書き出しはHTML書き出しと同じ構造・画像解決結果をAppKitの文字レイアウトに読み込み、A4・48pt余白のPDF印刷操作でページ分割する。保存は標準パネルで場所を選び、変換または印刷に失敗した場合はエラーを表示する。

印刷もPDF書き出しと同じ文字レイアウトと段落単位のページ分割を使う。標準のページ設定で用紙・向きを変更し、印刷設定シートで上下左右の余白と書類名ヘッダー・ページ番号フッターを選ぶ。実際の出力はmacOS標準の印刷パネルに渡す。用紙設定は書類画面ごとに保持し、本文のMarkdownには保存しない。

書式付きコピーはエディタの現在の選択範囲だけを別のMarkdown断片として解析し、HTML・RTF・表示用プレーンテキストを同時にクリップボードへ書く。通常のコピーは原文を保持する。断片内だけでは解決できない参照定義は変換しない。

プレーンテキスト書き出しは共通のブロック解析結果から見出し・段落・引用・リスト・コード・表の内容を抽出する。インラインの装飾はFoundationのMarkdown解析で除去し、リンク先と画像説明を選択に応じて追加する。脚注は`[^id]`形式の定義と参照を対象にし、コードブロック内の同じ文字列は残す。UTF-8の`.txt`へ保存し、元のMarkdownは変更しない。

HTML・PDF書き出しのプリセットは編集表示設定と別のUserDefaultsキーに保存する。本文幅・フォント・文字サイズ・余白・表紙・目次を持ち、標準設定は常に利用できる。HTMLではCSSと見出し索引に反映し、PDFでは余白と文字レイアウトへ渡す。表紙を選んだPDFは本文を次ページから開始する。書き出し時の一時的な設定変更はプリセット保存を押すまで保存しない。

ワークスペースは利用者が選んだフォルダのブックマークを保存し、Markdown・プレーンテキストと代表的な添付を再帰的に索引化する。ファイル一覧はサイドバーのアウトラインと切り替える。Markdownは既存の`DocumentGroup`で開き、添付はシステム既定アプリへ渡す。シンボリックリンク・隠しファイルを除き、深さ16・項目数1万の上限を設ける。外部変更には表示中3秒間隔の再走査で追従し、読み込みはバックグラウンドで行う。

クイックオープンはワークスペースのファイル索引からMarkdown・テキスト書類だけを対象にする。入力語を大文字小文字・アクセントを無視して照合し、連続一致とファイル名一致を優先する。候補は最大50件に絞り、確定後は既存の`DocumentGroup`で開く。

ワークスペース内の作成・改名・移動・ゴミ箱への移動はファイルツリーのコンテキストメニューから行う。改名と移動ではワークスペースの全書類を確認して、移動対象を指すインラインリンク・画像リンク・参照定義、および移動する書類自身の相対リンクを更新する計画を先に表示する。適用前に書類の追加・削除と内容変更を再検査し、移動対象自体が開いている場合は操作を止める。書き換え途中の失敗では元データと移動元へ戻す。ゴミ箱移動では影響を受けるリンク数を示し、リンクは残す。パス比較はシンボリックリンクを解決し、`/var`と`/private/var`のような別表記で更新漏れが起きないようにする。

ファイル一覧のピン留め、名前順・更新日時順、書類・添付・拡張子のフィルターは、ワークスペースのルート別にUserDefaultsへ保存する。拡張子候補は索引に現存するファイルから作る。フィルターは表示にだけ適用し、検索やリンク更新に使う元の索引は維持する。フォルダの改名・移動では子項目のピン留めも新パスへ移し、ゴミ箱移動では対象配下のピン留めを除去する。

新規書類の本文は`WorkspaceDocumentTemplate`で決め、保存先はワークスペースの選択フォルダから決める。空白を既定にし、従来のDocumentGroup新規書類は既存のスターター本文を維持する。書類は排他作成し、本文の書き込みに失敗した場合は作成したファイルを除去する。

文字コードを指定した取り込みは、元ファイルを読み込んで候補ごとの先頭プレビューを示し、選択した形式へ別ファイルとして変換保存する。デコードとエンコードの往復検査で損失や置換文字が生じる候補を拒否する。通常のDocumentGroupはUTF-8書類を編集するため、UTF-8への変換保存後のみその書類を開く。元ファイルを暗黙には書き換えない。

UTF-8書類の改行形式とBOMは本文から分けて`MarkdownDocument.format`に保持する。編集モデルへ渡す本文はLFに統一し、保存時に読み込み元のLF・CRLF・CRとBOMを再生成する。文字コードメニューで明示的に改行形式とBOMを切り替えると、本文文字列を変更せず保存形式だけ変わる。混在改行は改行の数が変わらない間は各行の元の形式を保持し、行数変更後は最多の形式（同数ならCRLF、次にCR）を使う。

書類ごとの作業位置は既存の`DocumentDisplayState`に選択範囲、編集スクロール位置、分割比、サイドバーの表示とアウトライン／ファイル選択を追加して保存する。本文ファイルには書き込まない。初めて保存した書類の表示モードだけが登録されている場合は位置を復元せず、現在の選択を維持する。復元する選択範囲は現在の本文長で切り詰める。分割位置はドラッグとアクセシビリティの増減操作で調整する。

フォルダ検索はセキュリティスコープを保持するワークスペースの索引をバックグラウンドで走査する。対象・除外のカンマ区切りglobを相対パスへ適用し、UTF-8本文を改行正規化して検索する。結果はUTF-16範囲と行番号を持ち、別書類を開いた後に既存の編集モデルへ選択範囲を渡す。検索は取り消し可能で上限2,000件とし、索引が切り詰められた場合は結果が不完全になるためエラーを示す。

複数ファイル置換は検索結果と各ファイルの元データから計画を作り、ファイルごとの局所的な変更前後をプレビューする。上限10,000一致で、対象ファイルを選べる。適用前に開いている書類と元データのSHA-256を確認し、選択した全ファイルを検査してから書き込む。書き込みが途中で失敗したときは触れたファイルを元データへ戻す。元の改行形式とUTF-8 BOMは`MarkdownDocument`の形式情報で保持する。

構造別検索は通常の文字列一致を`MarkdownAnalysis`のブロック範囲で絞る。コード、見出し、本文の順に優先判定するため、引用内のコードも本文へ紛れない。本文には段落、リスト、引用、表を含む。全体検索と一括置換で同じ構造フィルターを使い、複数ブロックをまたぐ一致は構造別検索から除外する。

プレビュー表示中の検索コマンドは`PreviewSearch`へ送り、UTF-16の原文一致範囲を編集モデルへ保持する。一致範囲を含むプレビューブロックへスクロールし、淡い背景で目印を付ける。次・前の検索は両端で循環し、検索語や本文が変わったときは古い目印を消す。編集表示では従来の`NSTextFinder`を使う。

リンク更新の計画には開いている参照元書類の未保存データを優先して使い、ディスク上の元データも別に保存する。複数ウインドウで本文が異なる場合や計画後に本文が変わった場合は中止する。適用中は対象エディタを一時的に編集不可にし、成功後に開いているバインディングへ更新後の本文を反映する。OSのファイル監視で更新後の本文が先に反映された場合も受け入れる。移動対象そのものが開いている場合はDocumentGroupの書類URLを安全に切り替えられないため、保存して閉じる必要がある。改行形式とBOMは読み込み時の形式を保持する。

文字数はSwiftの`String.count`でユーザーが知覚する文字単位を数え、空白除外は改行・空白文字を除く。選択範囲はNSTextViewのUTF-16範囲から切り出して計算し、現在セクションは最も近い見出しから次の同階層以上の見出し直前までとする。統計はMarkdown原文を対象にし、記号も文字数に含む。

語数は従来の空白区切りを初期値として保持し、日本語・英語の選択時のみ`NLTokenizer`の単語単位を使う。句読点と空白は単語として数えない。対象はMarkdown原文で、記号を含む文書と単語分割言語の指定は統計ポップオーバーに明示する。選択はアプリ設定として保存し、既存の設定データでは空白区切りに戻す。

読了・音読時間は日本語なら空白除外の文字数、英語なら単語分割の語数を、利用者が設定した毎分の速度で割って切り上げる。言語ごとの読む速度と音読速度を別々に保存する。表示には「目安」「約」を付け、Markdown原文に基づく推定であることを伝える。日本語の計算には記号も含み、英語の単語分割は句読点を除外する。空の本文は時間を表示しない。

執筆目標とセッション開始時の文字数は書類パスに紐づく表示設定として保存する。セッションの増減は現在の全文文字数との差で求めるため、削除も負数として表す。改名・移動時は既存の書類表示状態と一緒に引き継ぐ。未保存書類ではウインドウ内の増減のみ表示し、目標の保存は書類保存後に可能とする。

Markdown診断は既存のリンク診断に見出しレベルの飛びと箇条書き記号の混在を加える。コードブロックはMarkdown解析のブロック種別により対象外とする。見出しは最初のレベル1と以後の段階的な深さを推奨し、リストは最初に現れた記号を基準にする。規則の無効化はアプリ設定に保存し、診断行から原文位置へ移動できる。診断結果は本文や規則の変更後に再計算する。

自動整形は箇条書き記号を`-`に統一し、見出し記号直後の空白を1個にし、意味を持たない行末空白を除く。2個以上の行末スペースによる明示改行、コードブロック、先頭のYAMLフロントマターは触らない。選択範囲は行単位に広げ、改行形式を維持する。適用前に行単位の差分を表示し、本文が計画時と同一の場合だけ単一のUndo操作として適用する。

校正設定はAppKit標準の連続スペルチェックと自動訂正を制御し、言語はNSSpellCheckerの自動判定または英語・日本語を指定する。ユーザー辞書はmacOSの機能に委ねる。Markdown解析のコードブロック、インラインコード、HTTP(S) URL上では現在のエディタの訂正・スペルチェックを一時停止する。URL末尾への継続入力は同じ文脈として扱い、隣接する通常本文に移れば再開する。

自動リンクはGFMの拡張を基準に、行頭・空白・指定区切り記号の後の`http(s)://`と`www.`、および裸メールアドレスを対象にする。末尾の句読点と対応しない閉じ括弧はリンクから除き、コードと既存リンクに重ねない。プレビューとHTML書出しの双方で同じ属性付けを使用し、Markdown原文は変更しない。

脚注はGitHubの`[^id]`参照と`[^id]:`定義を採用する。番号は本文での最初の参照順とし、未参照の定義は脚注一覧に出さない。定義は本文ブロックから除き、コード内の同形文字列は対象外にする。構造化プレビューには脚注一覧と参照元へ戻るボタン、HTMLには相互アンカーを付ける。Markdown原文には番号を書き戻さない。

YAMLフロントマターは文書先頭の`---`から次の`---`または`...`までを原文範囲付きで保持する。本文の解析・HTML・印刷には含めず、プレビュー設定を有効にしたときだけ原文をメタデータ欄として表示する。YAMLの値を再解釈・再保存せず、本文に独自形式を混ぜない。閉じ区切りがなければ通常のMarkdownとして扱う。

コールアウトはGitHubの引用先頭行`[!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]`、`[!CAUTION]`だけを認識する。マーカー行は本文の子ブロックに含めず、引用の親ブロックに種別を保持する。プレビューでは種類ごとのSF Symbolとラベル、HTMLでは意味を示す`aside`を表示する。未知の種別は通常の引用として扱い、原文は変更しない。

脚注挿入は原文にあるすべての`[^id]`を調べて`fn1`から未使用IDを選び、選択末尾へ参照、文末へ定義を加える。両箇所を含む末尾範囲の差分編集としてまとめ、定義の本文開始位置へカーソルを移す。改行形式を保持し、IME変換中や編集拒否時は既存の編集モデルが操作を中止する。

ブロック変換は選択範囲を行単位に拡張し、各行の改行形式と字下げを保持する。引用コマンドは全行が引用なら引用記号を一層だけ外し、全行がリストならリスト記号を引用記号へ置き換え、混在していれば未引用行だけに付ける。引用からリストへの変換では外側の引用記号を外してリスト記号へ置き換える。「本文に戻す」は各行の最も外側にある引用・リスト・見出し記号を一層外す。入れ子の子項目そのものの文字列は残し、複数行を一つの差分編集として適用する。

書式除去はインライン構文だけを対象にする。空選択ではカーソルを含む最も小さい構文、範囲選択では完全に含まれる構文を解除する。強調・取り消し線・コードスパンは中身を残す。リンクは「表示名 (URL)」、画像は「代替テキスト (URL)」とし、タイトル属性は捨てる。リンク先のアンダースコアなどは書式記号として再解釈しない。フェンス付きコードブロック内の原文は保持する。ブロックの解除は別の「本文に戻す」コマンドで行う。

Markdown目次は既存の`MarkdownHeadingIndex`と同じ見出しIDを使い、標準のリンク付き箇条書きとして生成する。最浅の見出しを字下げゼロとし、見出し階層に応じて2スペースずつ字下げする。選択範囲があればその範囲だけを置き換え、選択範囲内の古い見出しを除いた本文からアンカーを再計算する。空選択ではカーソル位置に独立したブロックとして挿入する。専用の目次マーカーは書き込まず、更新対象の選択は利用者が指定する。

番号付きリストの再採番は`MarkdownAnalysis`の親IDで兄弟項目を特定し、途中に別種のブロックがない連続項目を一組とする。組の最初の番号を開始番号として保持し、子リストの番号は別に扱う。カーソルが項目内にある場合はその組だけ、複数項目を選択した場合は該当する各組を更新する。番号以外の区切り記号、本文、改行は原文のまま残し、変更範囲を一つのUndo操作にまとめる。

行の複製・上下移動・削除は選択範囲を完全な行へ拡張する。選択の終点が次の行の先頭に一致する場合、その次の行は含めない。複製後は新しい行を選択し、移動後は移動した行を選択する。最終行に改行がなければ、複製時に文書の改行形式で区切りを補い、削除時には直前の区切りも除く。上下移動では隣の行と1回の差分編集で交換し、最終行の改行有無を変えない。

Markdownコメントは標準のHTMLコメント`<!-- ... -->`を使用し、インライン選択と複数行選択の両方を一つの構文で囲む。カーソルが既存コメント内にあれば外側の記号と追加した両端の空白を外す。未選択時は空のコメントを挿入して内側へカーソルを置く。内容に`--`があるとHTMLコメントとして不正になるため、コマンドを無効にして本文を変更しない。

選択拡大は原文のUTF-16範囲を使い、カーソルまたは現在の選択を完全に含む最小のリンク、段落・コードブロック、子要素を含むリスト項目、見出しセクション、全文へ進める。コード内のリンクに見える文字列は候補にしない。編集モデルが選択履歴と本文のスナップショットを保持し、縮小では一段前へ戻す。手動の選択変更や本文編集があれば履歴を破棄し、古い範囲へ戻さない。

折りたたみは`MarkdownFoldPlan`で見出しセクションまたはコードブロックのヘッダー後の原文範囲を計算し、TextKit 1の`NSLayoutManagerDelegate`でその範囲のグリフを`.null`にする。文字列とUndo履歴は変更せず、行番号欄に折りたたみ印を示す。コピーは標準の原文選択を使用する。選択・検索・ナビゲーションが隠れた範囲へ移動したらその範囲を展開し、本文が編集されたら全折りたたみを解除して古いUTF-16範囲を残さない。参考: [Appleのグリフ生成デリゲート](https://developer.apple.com/documentation/appkit/nslayoutmanagerdelegate)、[nullグリフ](https://developer.apple.com/documentation/appkit/nslayoutmanager/glyphproperty/null)。

スニペットはアプリ設定へ短縮語とテンプレートを保存する。カーソル直前の単独の短縮語にTabを押すか、メニューでテンプレートを選ぶと、同じ`MarkdownEdit`で挿入する。`${1:初期値}`、`${2:初期値}`の番号順に入力範囲を選択し、Tab／Shift-Tabで移動する。`$0`は最後のカーソル位置を指定する。現在の入力範囲内で文字数が変わった場合は後続範囲のUTF-16位置を補正し、範囲外の編集ではセッションを終了する。通常の表セル移動・インデントはスニペット操作がない場合に従来どおり実行する。

コマンドパレットは`EditorCommand`の共通定義を一覧とし、操作名または表示用ショートカットで検索する。各候補は既存の`canExecute`で現在の編集モデルと選択を確認し、選択後は既存の`perform`を呼ぶ。利用不可の操作は候補から除外する。起動はCommand+Shift+Pとメニューから行い、Returnで最初の一致を実行し、Escapeで閉じる。

リモート画像はアプリ設定で明示的に有効化したときだけHTTP(S)から非同期で取得する。本文の画像構文と参照形式画像を対象とし、コード内の同形文字列は取得しない。1画像10MBを上限にサムネイル化し、メモリキャッシュを40MBまで使う。取得中・失敗・読込オフは代替テキスト付きで表示し、プレビューの画像取得完了時は描画キャッシュの世代を更新する。設定を無効化するとキャッシュを消す。取得に失敗したURLは再試行の連続発生を避けるため記録し、設定の再有効化後に再試行できる。

画像の拡大確認は画像添付に専用リンクを付け、構造化プレビューとテキストプレビューの双方で同じシートを開く。ローカル画像はmacOSの`QLPreviewView`を使い、リモート画像はサムネイルとは別に保持した取得済みデータから原寸を表示する。外部URLを再取得せず、読込設定を無効にすると原寸データも消す。シートを閉じると元のプレビューを作り直さないため、スクロール位置は維持される。専用リンクが扱う宛先はfile/HTTP(S)だけに限定する。参考: [Apple Quick Look UI](https://developer.apple.com/documentation/quicklookui)。

画像の幅指定にはPandocで一般的な`![説明](画像){width=320}`（`px`も可）を採用する。幅は1〜9999pxに制限し、プレビューとHTMLの両方に反映する。画面幅より大きい画像は指定幅の有無にかかわらず表示幅に縮める。画像だけの段落は代替テキストをキャプションとして併記し、HTMLでは`figure`/`figcaption`を使う。標準Markdownだけで共有する場合は幅属性を省き、画像の次の段落にキャプションを通常の文章または強調として置く。代替テキストは視覚上の説明文とは用途が違う場合があるため、両者を分けたい文書では標準Markdownの別段落方式を使う。

画像のリサイズ・圧縮は挿入ダイアログで明示的に「派生画像を作成する」を選んだ場合にだけ実行する。最大幅・最大高さを指定し、縦横比を保って縮小する。形式はPNG・JPEG・HEIC、画質はJPEG・HEICで指定する。処理はバックグラウンドで行い、同じ内容の既存画像を再利用し、名称が衝突したときは連番を付ける。元画像は文書フォルダ内にあっても変更せず、`assets`へ新しい画像を作る。本文が挿入前に変わった場合は今回作った派生ファイルだけを巻き戻す。

添付監査はワークスペース索引内の全Markdown書類を読み、開いている書類は未保存の本文を優先する。コードブロックとコードスパンを除外して画像・添付リンクを解決し、参照元の書類を保存する。欠落先、`assets`内の未使用候補、参照中の添付を分けて表示する。索引が上限で途切れた場合は結果を出さずエラーにし、誤った未使用判定を避ける。未使用候補はFinderで表示するだけで、自動削除しない。画像以外の添付としてPDFも参照を集計する。

一般のファイル添付は既存のリンク挿入画面から選び、通常の`[表示名](相対パス)`を生成する。保存済み書類では`assets`へのコピーと元ファイルへの相対参照を選択できる。コピー時は同一内容・同一拡張子を再利用し、別内容の同名ファイルには連番を付ける。書類本文の変更でリンクを確定できなければ、今回作成したコピーだけを巻き戻す。プレビューでは存在するローカル添付リンクをQuick Lookで開き、Markdown書類へのリンクは従来の書類移動を使う。未保存書類には相対パスの基準がないため、先に保存を求める。

参照形式とインライン形式の変換はカーソルが含まれる単一のリンクだけを対象にする。インラインからの変換ではURLとタイトルが一致する既存定義を再利用し、なければ表示名から一意のIDを作って文末へ定義を追加する。参照から戻す場合も定義は残し、他のリンクを壊さない。変換は一つの`MarkdownEdit`でUndoでき、コードブロック・コードスパン内は対象外にする。

ブックマークは保存済み書類のURL、UTF-16位置、周辺48文字、直前の見出しIDと見出しからの相対位置をアプリ設定に保存する。移動先の文書では同じ見出しセクション内の周辺文字列を優先して探し、見つからなければ見出しからの相対位置、見出しも消えていれば元の位置に戻す。同じ本文が別セクションにあっても誤移動しないよう検索範囲を制限する。サイドバーから追加・移動・削除でき、ワークスペースの改名・移動では書類URLを更新する。本文の位置は文字列と構造からの推定であり、編集内容によっては近傍へ移る。

セクション移動はアウトラインの見出しを起点とし、次の同階層以上の見出し直前までを子見出しを含む一単位にする。同じ親を持つ隣の同階層セクションとのみ交換する。境界の改行は位置に残し、CRLFと最終改行の有無を保持する。交換はひとつの範囲編集として適用し、Undoを一回で戻せる。

セクションの昇格・降格もアウトラインの見出しから次の同階層以上の見出し直前までを対象とし、その範囲にある見出しレベルを一律に1つ変える。一つでもH1〜H6を外れる場合は全体を変更しない。Setext見出しはATX見出しへ変換し、本文と改行形式は保持する。変更は一つの範囲編集として適用する。

現在文書のインスペクタは共有済みの`MarkdownAnalysis`からタスクを集め、リンク・画像は原文の範囲を保持したままインライン形式と参照形式を索引化する。コードブロックとコードスパン内の同形文字列は除外する。タスク・リンク・画像を別セクションに表示し、選択した項目の原文位置へ移動する。フォルダ横断の集計とは別画面とし、解析中は古い本文の項目を表示しない。

分割表示は左右・上下とプレビューの先頭配置を文書ごとの表示状態に保存する。仕切り位置の比率は編集ペイン側の大きさとして保持し、上下や左右へ切り替えても同じ比率を使う。仕切りは8ptの操作範囲と1ptの表示線を持ち、ドラッグ・アクセシビリティ調整に対応する。十分な画面幅では両ペインの最小幅を確保し、狭いウインドウでは均等に縮める。本文とUndo状態は既存の編集モデルに残す。

別ウインドウのプレビューは現在の`FileDocument`バインディングを受け取り、独立した書類の読み込みや保存はしない。元の書類側を閉じたらプレビューも閉じ、手動でプレビューを閉じた場合は次回の操作で再作成する。別名保存で書類URLが変わればプレビューの相対リソース解決とウインドウ名を更新する。本文の編集とUndoは元の書類側でだけ行う。

コードブロックのコピーは構文解析済みブロックの`content`をプレーンテキストとしてクリップボードへ設定する。フェンス、言語名、プレビューの表示属性は含めない。コードブロックがある文書は構造化プレビューで表示し、分割・プレビュー専用・別ウインドウのすべてで同じボタンを使う。

プレビュー更新の停止は書類本文を変更せず、表示用の原文とその解析結果を同一世代として保持する。本文が変わるたびに原文世代を進め、停止中は表示世代を固定する。手動更新で最新本文を取り込み、自動更新の再開で固定内容を破棄する。解析結果がまだない世代を取り込んだ場合はバックグラウンドで解析し、完了するまで準備表示を出す。分割表示、プレビュー専用表示、別ウインドウは一つの停止状態を共有する。停止中に原文と表示世代が異なるときは、範囲がずれるタスク切替・原文への移動・スクロール同期を無効にする。

明示スナップショットはmacOSの自動保存・「バージョンを戻す」と別の、利用者が名前を付ける履歴として扱う。保存済み書類のシンボリックリンクを解決した標準化URLをハッシュ化し、Application Supportの書類別フォルダへ本文を個別のUTF-8ファイルで保存する。索引は名前・日時・IDだけを持ち、履歴一覧の表示で巨大な本文を全部読み込まない。保存時は本文を先に原子的に書き、索引更新が失敗したら本文ファイルを除去する。比較は行単位の差分をバックグラウンドで計算し、本文が再変更された場合は古い比較結果を表示しない。変更箇所ごとに示し、各箇所または全文を現在の書類へ戻す。復元直前に現在本文の一致を確認し、編集中は既存の差分編集・Undo経路を使う。書類が未保存なら履歴操作を表示しない。

フォルダ別設定は既存の表示モード・文字サイズ・画像のコピー／参照方式に、タブ幅、リストとコードの字下げ幅、添付保存先、Markdown構文プロファイルを追加する。値は最も近い親フォルダの明示設定を優先し、なければアプリ共通設定を使う。保存先は安全な単一フォルダ名`assets`または`images`だけを選べるようにし、画像の挿入・派生画像・貼り付け、一般添付、添付監査を同じ規則で扱う。構文プロファイルの「基本」は表・脚注・YAMLフロントマターを拡張構文として解釈せず、プレビューとHTML/PDF書き出しへ反映する。「拡張」は従来の解析を維持する。設定変更時は同じ本文も再解析し、解析結果を本文とプロファイルの組で照合する。

DOCX・ODT・EPUB書き出しには任意導入の[Pandoc](https://pandoc.org/installing.html)を使用する。基本プロファイルは`commonmark`、拡張プロファイルは`markdown`を入力形式に指定し、外部変換器が解釈する構文差を画面で案内する。書類の未保存本文を一時Markdownファイルへ書き、画像の探索先に書類フォルダを指定する。変換結果は出力先と同じディレクトリの一時ファイルに受け、正常終了・非空出力・保存先が変換中に変わっていないことを確認してから置き換える。失敗・中止時は既存出力と原文を変更しない。Pandocがない環境ではUIに導入先を示すが、アプリに同梱・自動導入はしない。Pandocの[対応形式とリソース探索の仕様](https://pandoc.org/MANUAL.html)を参照した。実物のPandocによる出力は開発環境に未導入のため未検証で、代替実行ファイルでプロセス・エラー経路を確認する。

HTML・RTF取り込みはファイルを最大10MBまで読み、AppKitの属性付き文字列を通して見出し、強調、リンク、箇条書きの基本構造をMarkdownへ変換する。HTMLの見出しタグは読込前にレベル印を付けて保持し、文字コードの宣言を確認してからUTF-8へ正規化する。画像は自動的に書類フォルダへコピーせず、代替テキストを含む位置表示へ置き換え、表・CSS・添付画像・一部装飾・相対リンクの喪失をプレビュー画面で案内する。取り込み元は変更せず、適用前の本文と一致するときだけ現在の書類を一回のUndo操作で置き換える。[Appleの属性付き文字列HTML読込](https://developer.apple.com/documentation/foundation/nsattributedstring/init%28data%3Aoptions%3Adocumentattributes%3A%29)はバックグラウンドスレッドから呼ばないよう案内しているため、ファイル読込だけをバックグラウンドにし、属性解析はMainActorで行う。

持ち出し用パッケージは保存済みの単一書類から作る。コード内を除く相対画像と、Markdown書類以外の相対ファイルリンクを集め、同名ファイルに連番を付けて`assets`へコピーする。Markdownのインライン形式・参照形式はパッケージ内の相対パスへ書き換える。HTMLでは既存の書出し処理によってローカル画像を埋め込み、添付へのリンクは`assets`へ向ける。外部画像と欠落したローカル参照は不完全な成果物を作らないようエラーにする。別のMarkdown書類へのリンクは対象書類を再帰的に収集しないため、そのまま残す。出力先に同名のフォルダ・ZIPがある場合は上書きせず、隠し一時フォルダで完成させてから移動する。添付の合計は500MBまでとし、元書類は変更しない。

一括書き出しは選択した対象フォルダを深さ16・最大10,000書類まで走査し、隠しファイルとシンボリックリンクを除く。Markdown・HTML・PDF・プレーンテキストを選べ、相対フォルダ構成を維持して各書類の拡張子を変える。開いている書類は未保存データのスナップショットを優先し、複数ウインドウの本文が不一致なら開始しない。フォルダの外へは書き込まず、各成果物を一時ファイルから移動して確定する。同名出力や同じ名前に変換される別拡張子の書類は先着の出力を保持し、後続を失敗一覧に示す。書類単位の読込・変換エラーは次の書類を止めず、取消時は処理中の書類の一時ファイルを除去し、成功済みの出力を残す。PDFの印刷処理中はAppKitの処理が戻った後に取消を反映する。HTML内の相対リンクは元書類基準のままであり、配布用に添付をまとめる用途には単一書類の持ち出し用パッケージを使う。

プレビューテーマは既定でmacOSの外観と動的な文字色に追従する。任意の紙色テーマは固定の明るい背景と暗い本文・見出し・コード色を使い、WCAGの相対輝度式で各文字色のコントラスト比7:1以上をユニットテストで確認する。本文最大幅は560〜1200ptの設定値を構造化プレビューへ適用し、文字倍率とは別にする。テーマを切り替えた際はプレビューの描画キャッシュを破棄し、原文・Undoには触れない。紙色テーマではコードの構文別色分けより選択した高コントラストの単色を優先する。

不可視文字とインデントガイドはNSTextViewの文字列や属性へ記号を書き込まず、原文のUTF-16位置から表示計画を作って描画時に重ねる。空白は中点、タブは矢印、改行は段落記号とし、行末空白は警告色で示す。ガイドは先頭の字下げで設定タブ幅ごとの境界に描く。設定はアプリ共通の表示設定とし、IME未確定中は重ね描きを避ける。計画は本文やタブ幅の変更時だけ更新し、保存内容とUndo履歴へ影響させない。

集中モードはウインドウごとの一時状態とし、入る直前のサイドバー表示を記録して隠す。ステータスバーも非表示にし、SwiftUIの[ウインドウツールバー表示制御](https://developer.apple.com/documentation/swiftui/view/toolbar%28_%3Afor%3A%29)でツールバーを隠す。Command+Shift+J、メニュー、画面右上のボタンで終了でき、元のサイドバー状態を復元する。フォーカス中に作業位置を保存する場合も、サイドバーの元の表示状態を保存し、再起動後に一時的な集中表示を残さない。文書本文とmacOSのフルスクリーン状態は変更しない。

ツールバーはSwiftUIの[カスタマイズ可能なtoolbar](https://developer.apple.com/documentation/swiftui/view/toolbar%28id%3Acontent%3A%29)と`ToolbarCommands`を使う。太字・斜体・リンクを初期表示し、他の書式・挿入項目は利用者が標準の編集画面から追加する。各項目は固定IDを持ち、メニュー・コンテキストメニューと同じ`EditorCommand`を実行するので、プレビュー専用や別ウインドウで編集不可のときはコマンドの共通有効条件を使う。カスタマイズ状態の保存はmacOSに任せ、本文や文書ごとの設定へ混ぜない。

ショートカット設定は共通の`EditorCommand`一覧から生成し、コマンドIDごとの変更値だけをアプリ設定へ保存する。キーは印字可能な1文字とし、CommandまたはControlを必須とする。保存前に他コマンドの現在値、書類・検索・ウインドウ操作の固定キー、macOSで標準的に使うCommand+Q/W/H/Mなどを検査する。変更はMarkdownメニューとコマンドパレットの表示・検索へ同時に反映し、「既定に戻す」で変更値だけを削除する。既存の本文見出し切替とプレビュー倍率のCommand+Option+0が重複していたため、プレビュー倍率のリセットをCommand+Option+Shift+0へ移した。ユーザー定義値はアプリ設定の移行可能な任意フィールドとし、既存設定を読み込んでも既定キーを保持する。

UIの原文言語は日本語とし、`Localizable.xcstrings`に英語訳を置く。SwiftUIの静的ラベルはXcodeの文字列抽出に任せ、動的なコマンド名、設定値、AppKitメニュー、エラー文、VoiceOver読み上げ文には`String(localized:)`を明示する。永続化されるenumの`rawValue`は変更せず、表示用の`title`を分ける。テンプレートと挿入時の仮文字列は作成時の言語で本文へ入るため、その後の表示言語変更で既存文書を書き換えない。Xcodeの`-exportLocalizations`で抽出結果を更新し、カタログテストで英語訳の欠落、未翻訳の日本語、置換引数の種類を検出する。Xcodeビルド後の`en.lproj/Localizable.strings`でも英語リソースを確認した。

外部からの書類指定は`mktowneditor://open?url=<file URL>&line=<1始まりの行>`に統一し、`Tools/mktown-open.swift`もこのURLをLaunch Servicesへ渡す。URLに含める書類形式と正の行番号を検証し、ファイルの読み書きは[DocumentGroup](https://developer.apple.com/documentation/swiftui/documentgroup)へ委ねる。[`NSApplicationDelegate.application(_:open:)`](https://developer.apple.com/documentation/appkit/nsapplicationdelegate/application(_:open:))は独自URLスキームを受け取り、[`NSDocumentController.openDocument`](https://developer.apple.com/documentation/appkit/nsdocumentcontroller/opendocument(withcontentsof:display:completionhandler:))で既存書類を再利用する。行移動依頼は書類URLで照合して共有ナビゲーションへ一時保持し、対象ウインドウの現在の本文からUTF-16位置を求める。本文が変わっていてもディスクを読み直して編集状態を上書きしない。失敗した依頼は破棄し、書類を開くエラーを表示する。

原文中のHTMLはWebViewで解釈せず、プレビューとHTML書き出しに共通の限定変換を適用する。許可するのは`b`/`strong`、`i`/`em`、`s`/`del`、`code`、`br`、`p`/`div`/`span`、安全な`href`を持つ`a`とし、装飾属性とイベント属性は使わない。`<!-- -->`コメントは表示しない。`script`、`style`、`iframe`、`object`、`embed`、`form`は内容ごと破棄して要素名を表示し、その他の未対応タグも名前を表示して本文テキストだけを残す。Markdownの自動リンクとコードスパン内のタグはHTMLとして扱わない。変換結果は原文へ書き戻さず、構文位置とUndoに影響させない。

複数選択はAppKitの`NSTextView.selectedRanges`を正本とし、ビュー再生成時にモデルが各範囲を保持して復元する。[`setSelectedRanges`](https://developer.apple.com/documentation/appkit/nstextview/setselectedranges(_:affinity:stillselecting:))が要求するグリフ境界の範囲をAppKitから受け取り、原文差分を安全に合成できる太字・斜体・取り消し線・インラインコードだけを複数範囲の書式コマンドとして提供する。差分は原文上で重ならないことを確認し、1回の`shouldChangeText`と置換でUndoを1単位にする。リンク編集、表編集、行操作など単一範囲を前提にするコマンドは複数選択中に無効化する。選択済みの文字列と一致する次の出現箇所を追加できる。矩形などの非連続選択も複数範囲として受け取るが、独自の矩形ドラッグ操作や等幅以外での視覚上の列揃えは追加しない。

表の行移動はデータ行だけを対象とし、ヘッダーと区切り行を固定する。列移動ではヘッダー・配置記号・各データ行のセルをまとめて入れ替える。ソートは選択列の前後空白を除いた値を`localizedStandardCompare`で比較し、同値の行は元の順序を保つ。列を選ぶ位置はヘッダーでも本文でもよい。操作後は移動したセルを選択し、表ブロックの差分を1回のUndoで戻せるようにする。改行は各行の位置に残し、CRLFをUTF-16単位で取り除く。Swiftの`String.dropLast(2)`はCRLFを1文字と扱う場合があるため、同じ行分割を使う一般の行移動処理も修正した。

表のグリッド編集は選択中の表だけを原文スナップショットとともに読み込む。画面ではヘッダー、セル、列配置、行・列数を編集し、確定時に表ブロックだけを`MarkdownEdit`で置き換える。原文が開いた時点から変わっていれば確定を拒否し、変更なしなら書き換えない。セルにはMarkdown原文を示し、未エスケープのパイプをエスケープし、改行は`<br>`に変換する。表の前後の本文と引用の接頭辞、改行形式、末尾改行の有無を保持する。

外部URLの到達確認はリンク診断画面の明示ボタンからだけ開始する。HTTP(S)のインラインリンク・画像と参照定義を対象にし、コード内とローカルパスは除外する。同一URLは1回だけHEADリクエストし、8秒でタイムアウトする。2xx・3xxは到達、401・403・407はアクセス制限、404・410だけを欠落、408・429・5xxと通信断は一時的な失敗として区別する。HEAD非対応などその他の応答は判定不能と表示し、リンク切れと断定しない。画面を閉じるか本文が変わった場合は実行中の確認を取り消す。

リンクのホバープレビューは原文エディタとプレビューのリンク文字列上で表示する。AppKitのグリフ矩形とリンク属性から対象を特定し、ポップオーバーを少し遅らせて表示する。クリックを消費せず、リンクを離れる・クリックする・本文が変わると閉じる。構造化プレビューではリンクを含むテキストだけを選択可能なAppKitビューにし、リンクのないブロックは従来のSwiftUI描画を維持する。ローカルMarkdownは1MB以下を読み、見出しフラグメントの節から抜粋する。同じ文書へのリンクは未保存の本文を使う。外部ページは既定で取得せず、設定で有効化したときだけ最大8KBのHTMLから題名を抽出し、失敗時はホスト名を表示する。

ミニマップは編集本文を再組版せず、UTF-16原文の行開始位置と各行の長さから最大600本の棒を作る。作成は入力停止後180msにバックグラウンドで行い、世代が古い結果を破棄する。更新中は直前の図を残すが、古い位置情報での移動は無効にする。表示範囲は実際のスクロールビューの高さ比率で重ね、クリック・ドラッグとVoiceOverの増減操作で原文位置へ移動する。アプリ設定で非表示にできる。開発環境での計画生成時間は約100KBで0.002秒、1MBで0.020秒、10MBで0.204秒だった（各1回、描画とファイル読込は含まない）。

## R01 数式（2026-09-29）

- 拡張Markdownで一行内の`$...$`と、`$$`だけの行で挟む複数行ブロックを採用する。基本方言では記号を原文表示する。
- `$5`や`$5 and $6`を金額として扱うため、閉じ記号直後の数字、空白に接する区切り、数字だけの内容を数式と判定しない。エスケープ、コードスパン、コードブロック内も除外する。
- macOS 14で動作するSwiftMath 1.7.3（MIT）を固定し、ネットワークを使わずネイティブに組版する。HTML/PDF書き出しにはPNGを埋め込む。解析不能な式は原文を残す。組版可能な範囲はSwiftMathの対応LaTeX記法に従う。
- 数式は本文とは別の画像として表示するため、HTMLにはLaTeX原文を代替テキストとして入れる。コード上はプレビュー、HTML、PDFの同一判定を用いる。

## R02 Mermaid図（2026-09-29）

- `mermaid`を指定したフェンス付きコードブロックだけを図にする。プレビュー内で原文へ切り替えられ、描画エラーでは図内の行番号と原文を表示する。HTML/PDF書き出しは現時点でコードブロックを維持する。
- Mermaid 11.17.0の単一ファイル配布物を同梱する（MIT、ライセンスファイルを同梱）。描画はWebKitの隔離されたページで行い、CSPで外部リソースを禁止する。本文を外部サーバーへ送らない。
- Mermaidの処理結果はメッセージハンドラーを通じて高さ・エラー・行番号だけをSwiftUIへ戻す。本文変更時は前のエラーを消して再描画する。正常な図と構文エラーをWebKitを用いるユニットテストで確認する。

## R03 外部図描画器（2026-09-29）

- `dot`/`graphviz`はユーザーが指定したGraphviz実行ファイル、`plantuml`/`puml`はユーザーが指定したJARをJavaで起動する。どちらも未指定なら実行せず、設定への案内と原文を表示する。PlantUMLには別途Java実行環境が必要。
- Graphvizは`-Tpng`と入力・出力ファイルのパスを引数配列で渡す。PlantUMLは`-pipe`で原文を標準入力へ渡し、`PLANTUML_SECURITY_PROFILE=SANDBOX`でURLとローカルファイルの参照を禁止する。シェルを通さず、プレビューの本文を外部サーバーへ送らない。
- 入力を256KB、出力PNGを10MB、実行を8秒に制限する。本文変更・画面消失・中止操作でタスクをキャンセルし、子プロセスへ終了要求を出す。標準エラーの先頭1200文字を失敗時に示す。書き出しではフェンス付き原文を維持する。

## R04 引用と参考文献（2026-09-29）

- 文書と同じフォルダの`references.bib`（UTF-8、最大1MB）を採用し、拡張Markdownの`[@key]`だけを引用とする。番号はBibTeXの登録順で固定し、未解決キーは原文を残す。コードスパンとコードブロックは置換しない。
- 引用は`[番号]`、参考文献は番号・著者・年・題名・掲載誌などの簡潔な固定様式で表示する。プレビュー、HTML/PDF、Pandocへの入力を同じ`MarkdownCitationCatalog`で生成するため、同じ番号と文面になる。参考文献ファイルの全項目を一覧へ載せる。
- BibTeXの波括弧と引用符、入れ子の値を読み、`@comment`、`@string`、`@preamble`は文献から除く。複雑なBibTeXマクロやLaTeX命令の展開は行わない。
- 開いているプレビューでは`references.bib`のサイズと更新日時を3秒ごとに確認し、変更時にキャッシュ済みの表示ブロックを再生成する。

## R05 図表・数式の相互参照（2026-09-29）

- 拡張Markdownでは対象ブロックの直後へ空行を置き、単独段落の`{#fig:id}`、`{#tbl:id}`、`{#eq:id}`を記す。IDは英字開始の英数字・ハイフン・下線とし、同じIDを再使用しない。図は単独画像、表はGFM表、数式は`$$`ブロックに限る。
- 番号は図・表・数式ごとに文書順で付ける。本文の`@fig:id`などは番号付きリンクへ変換し、プレビューでは対象へスクロール、HTMLでは同じIDのアンカーへ移動する。PDFもHTMLを経由して同じ番号を使う。コード内と未解決IDは原文を残す。
- `MarkdownAnalysis`の位置付きブロックからIDと対象を一度解決し、プレビューのキャッシュキーにも反映する。編集で対象や番号が変われば参照表示を更新する。重複ID、対象種別不一致のマーカーは隠さず原文として表示する。

## R06 定義リスト（2026-09-29）

- 拡張Markdownの単一段落で`用語`の直後に`: 説明`を置く記法を採用する。複数の説明と用語を続けられ、説明の継続行は2スペース字下げとする。段落全体がこの構造に合う場合だけ変換し、通常の文章やコード、基本方言は原文のまま扱う。
- 元の段落ブロックとUTF-16範囲を維持したまま解釈する。ネイティブ表示では用語を強調し説明を字下げし、HTML/PDFは`dl`・`dt`・`dd`へ変換する。プレーンテキスト書き出しには用語を各説明へ付記する。

## R07 ハイライト・上付き・下付き（2026-09-29）

- 記法は属性なしの`<mark>文字</mark>`、`<sup>文字</sup>`、`<sub>文字</sub>`に限定する。タグ内は改行・別のHTMLタグを含まないプレーンテキストとし、コードスパン、コードブロック、エスケープ済みの開始タグは変換しない。基本方言と未対応のHTML属性は従来の安全なHTML処理へ委ねる。
- 書式コマンドは選択文字列をタグで囲み、再実行で囲みを外す。プレビューはAppKitの背景色・ベースライン属性で描画し、HTML/PDFは安全にエスケープした本文とタグを出力する。プレーンテキスト書き出しではタグを除く。未対応のMarkdown処理系ではHTMLタグがそのまま見える場合がある。

## R08 絵文字ショートコード（2026-09-29）

- アプリ内に55種類の英小文字ショートコード辞書を持つ。既知の`:name:`をプレビュー・HTML/PDF・プレーンテキスト書き出しでUnicode絵文字へ変換し、未登録名、コード、エスケープ済み記法、基本方言はそのまま残す。外部辞書やネットワークを必要としない。
- 補完にはAppKit標準のF5候補パネルを使う。コロンからカーソルまでを補完範囲にし、候補は辞書から最大30件を名前順に提示する。コード内、IME変換中は候補を出さない。メニューにも補完操作を置く。Unicode絵文字の直接入力はmacOSの既存機能に委ねる。

## R09 ローカル音声・動画（2026-09-29）

- 拡張Markdownの単独行`!audio[説明](相対パス)`と`!video[説明](相対パス)`を採用する。音声はMP3・M4A・AAC・WAV、動画はMP4・M4V・MOVに限り、保存済み文書から解決できる通常ファイルだけをAVKit標準コントロールで再生する。再生はユーザー操作で開始し、ビューを閉じたら停止する。外部URLは再生しない。
- プレビューには元ファイルを開くリンクも置く。HTML/PDFはメディアを内包せず元ファイルの`file:`リンクと説明を出力するため、ファイルの移動後はリンクが無効になる。未保存・欠落・形式不一致では再生不可の代替テキストを出す。通常のMarkdown処理系ではこの記法が文字列として表示される場合がある。

## R10 スライド表示とPDF（2026-09-29）

- スライド表示を明示しているときだけ、文書の最上位にある単独の水平線`---`を境界とする。通常プレビュー・HTML・通常PDFでは水平線として維持する。見出し直後の`---`はSetext見出しとして扱うため、スライド境界の前後は空行にする。先頭の`---`は、後続の最初の内容行が`key: value`形式で閉じフェンスがある場合だけYAML前付けとみなす。
- 発表は別の全画面ウインドウで現在の文書のスナップショットを開き、前後ボタン・矢印キーで移動する。スライドPDFは通常PDFとは別経路で、各スライドのHTML表示を横長842×595ポイントの1ページへ描く。長いスライドは縮小して収める。

## Z01 Gitの差分と履歴（2026-09-29）

- 保存済み書類の親フォルダからGitのルートを調べ、フォルダ全体の短い状態、現在の書類のHEADとの差分、書類に関する直近40件のコミットを読み取る。履歴から選んだコミットの本文を読み取り専用で表示する。未コミットのリポジトリでは状態だけを表示する。
- `/usr/bin/git`を`Process`の実行ファイルとして指定し、パスとハッシュは個別の引数で渡す。シェル展開を使わず、標準出力は一時ファイルへ受け、8秒・4MBの上限を置く。読み取りはバックグラウンドで行い、画面の更新操作で再取得する。差分はディスク上の保存済み内容を対象とし、編集中の未保存バッファは含めない。

## Z02 Gitのステージとコミット（2026-09-29）

- `git status --porcelain=v1 -z`で特殊文字を含むファイル名と競合状態を取得する。通常の変更はファイル単位で選択し、差分を確認してステージ・取り消しする。コミットには現在ステージ済みの全ファイルを明示選択し、空でないメッセージを入力する必要がある。既に別の操作でステージされたファイルも一覧に含める。
- 競合ファイルは通常のステージ操作から外し、編集で開く操作と解消済みとしてステージする操作を分ける。後者は競合記号を含むファイルを拒否する。Git操作はすべて`Process`の引数配列で行い、コミット時はリポジトリのフック実行を無効化する。push・pullなどの通信は提供しない。

## Z03 クラウドファイル状態と競合版（2026-09-29）

- `DocumentGroup`の保存とファイルプロバイダを正本にし、URLのリソース値からiCloudのダウンロード状態・競合の有無・ディスク更新日時を表示する。未ダウンロードのファイルは利用者の操作でダウンロードを開始する。
- [`NSFileVersion`](https://developer.apple.com/documentation/foundation/nsfileversion/unresolvedconflictversionsofitem(at:))の未解消版を協調読込で開き、編集中の本文と並べて比較する。選択版の採用は通常のUndo可能な編集とし、ディスクへの保存を確認するまでは競合版を解消扱いにしない。解消確定時には未解消版だけを取り除く。
- ローカルファイルと欠落ファイルのユニットテストを用意した。iCloudや第三者ファイルプロバイダが実際に生成する競合版の操作は、実アカウントと実ファイルでの確認が必要であり、ローカルのテストでは再現できない。

## Z05 macOSサービスとショートカット（2026-09-29）

- [macOS HIG](https://developer.apple.com/design/human-interface-guidelines/app-shortcuts)ではmacOSのApp Shortcutsフレーズは対象外だが、App Intentsのアクションはショートカットアプリから利用できる。このため、テキストをフォルダに保存するアクションと、保存済みMarkdownを既存レンダラーでHTMLへ書き出すアクションを定義した。自動化入力は明示的なテキスト・ファイル・保存先パスとし、開いている未保存書類を暗黙に取得しない。
- [Services](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/SysServices/Articles/providing.html)には選択文字列を渡すサービスを登録した。保存パネルで保存先を確定し、生成した書類を標準書類管理で開く。共通の書込処理は排他的なファイル作成により既存ファイルを上書きせず、単体テストでUnicode・同名ファイル・不正な名前・HTML出力を検証する。
