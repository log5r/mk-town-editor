# Markdownのプレビュー設定

macOS版では、「MKTownEditor」→「設定…」（⌘,）→「プレビュー」で表示を変更する。既存の設定ウインドウを使い、「表示」「Markdownの解釈」「フロントマター」の項目に分ける。設定はアプリ全体に適用し、変更直後に反映・保存する。

iPhone / iPhone Duo版では書類画面の歯車の「設定」ボタンから画面を開く。「Markdownの解釈」と「フロントマター」で同じ3項目を切り替え、「完了」で閉じる。設定はiOSアプリ内の全書類に適用し、macOS版とは別に保存する。フロントマターの既存の設定値も引き継ぐ。

## 段落内の改行

「本文の改行をそのまま表示」の初期値はオフ。オフでは、通常の段落内の改行1つを空白として表示する。オンでは同じ位置で改行する。行末の半角スペース2つやバックスラッシュによる明示的な改行、空行による段落の区切り、コードブロックの改行は維持する。リスト・タスクリスト・引用・コールアウトの本文にも適用する。

この設定はプレビュー専用で、原文と書き出しには影響しない。通常のプレビュー、別ウインドウのプレビュー、埋め込み文書に適用する。プレビューの自動更新を一時停止している場合も、表示中の原文に対して設定を反映する。

## フロントマター

「プレビューにフロントマターを表示」で先頭のYAMLの表示を切り替える。「Obsidianのプロパティを整形して表示」は、フロントマターを表示しているときに変更できる。表示をオフにしても整形の選択は保存する。改行設定とは独立して保存し、YAML自体の改行は変更しない。

## 実装と検証

`AppEditorSettings.preservesSoftLineBreaksInPreview` は省略可能な値として保存し、項目のない旧設定ではオフとする。描画時に `DocumentContext.preservesSoftLineBreaks` として渡し、解析結果や原文を変更せず、`MarkdownRenderer.paragraphContent` で段落内の区切りを決める。

iOS版は `mobile.preservesSoftLineBreaksInPreview` を `AppStorage` で保存する。`MobileMarkdownPreview.Block.displayText` でFoundationの `softBreak` 属性の箇所を空白または改行として表示する。通常の改行と明示的な改行・コードを解析結果から区別できるため、設定だけを変更した場合は再解析しない。

改行設定は `DocumentContext` の同値判定に含める。これにより、同じ原文・解析結果を表示していても、設定変更時に構造化プレビューのキャッシュと通常のテキストプレビューを更新する。埋め込み文書は保持済みの解析結果から描画を更新し、表示設定の変更だけではファイルを読み直さない。

テストは、初期値と旧設定の読み込み、オン・オフの保存、フロントマター設定との独立性、基本・拡張Markdownの描画、明示的な改行・空行・コードの維持、リスト・引用・コールアウトへの適用を検証する。同じ解析結果で改行設定を往復した際の描画キャッシュ、実際のテキストプレビュー、埋め込み文書の描画結果も確認する。

iOS版の画面テストでは、書類ツールバーの設定ボタンからシートを開き、3つのスイッチが表示されることと、操作による設定の即時反映を確認する。ツールバーの取得には `rightBarButtonItems` に加えて `trailingItemGroups` も参照する。OSによって `UIBarButtonItem` 自体にはアクセシビリティ識別子が渡らない場合があるため、項目の取得だけで判定せず、開いた画面のスイッチまで検査する。
